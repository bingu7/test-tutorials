# 学习路线与项目实战模块需求

## 一、背景

当前项目已经覆盖软件测试基础理论、常用工具、专项测试、自动化测试和持续集成，内容体系较完整。下一阶段的重点不是继续堆叠零散知识点，而是补齐“怎么学”和“怎么练”的闭环，让读者能够按照清晰路径完成从入门到实战的学习。

## 二、建设目标

新增两个相互配合但职责不同的模块：

- **学习路线**：作为学习地图，告诉读者先学什么、后学什么、每个阶段要达到什么程度。
- **项目实战**：作为练习场，把已有教程中的知识串成真实测试工作流程。

最终让网站从“教程资料库”升级为“软件测试学习体系”。

## 三、模块边界

### 3.1 学习路线

学习路线是导航型页面，重点解决：

- 不同基础的读者应该从哪里开始。
- 每个阶段推荐学习哪些教程。
- 学完后应该做哪些练习。
- 什么时候可以进入下一阶段。

建议文件：

```text
docs/学习路线.md
```

### 3.2 项目实战

项目实战是练习型内容，重点解决：

- 如何把理论、工具和自动化串起来。
- 如何按真实测试流程拆解需求、设计用例、执行测试、提交缺陷和输出报告。
- 如何积累可以用于面试和工作复盘的项目经验。

建议文件：

```text
docs/项目实战/index.md
docs/项目实战/电商系统测试实战.md
docs/项目实战/接口自动化项目实战.md
docs/项目实战/Web自动化项目实战.md
```

## 四、第一阶段范围

第一阶段先完成最小可用版本：

1. 新增 `docs/学习路线.md`。
2. 新增 `docs/项目实战/index.md`。
3. 新增 `docs/项目实战/电商系统测试实战.md`。
4. 更新 `mkdocs.yml` 导航。
5. 更新 `README.md` 的教程数量、学习路线和教程目录。
6. 执行 `mkdocs build --strict` 验证。

## 五、第二阶段范围

第二阶段在第一阶段基础上继续补齐项目实战模块：

1. 新增 `docs/项目实战/接口自动化项目实战.md`。
2. 新增 `docs/项目实战/Web自动化项目实战.md`。
3. 更新 `docs/项目实战/index.md`，把两篇新实战加入推荐训练顺序。
4. 更新 `mkdocs.yml` 导航。
5. 更新 `README.md` 与 `docs/index.md` 的文档数量和项目实战分类。
6. 执行 `mkdocs build --strict` 验证。

## 六、第三阶段范围

第三阶段继续补齐项目实战模块中的进阶能力：

1. 新增 `docs/项目实战/性能测试项目实战.md`。
2. 新增 `docs/项目实战/CICD自动化回归实战.md`。
3. 更新 `docs/项目实战/index.md`，让项目实战形成完整训练顺序。
4. 更新 `docs/学习路线.md` 中的项目实战入口。
5. 更新 `mkdocs.yml` 导航。
6. 更新 `README.md` 与 `docs/index.md` 的文档数量和项目实战分类。
7. 执行 `mkdocs build --strict` 验证。

## 九、验收标准

- 新增页面能够被 MkDocs 导航正确访问。
- README 中教程数量与导航内容保持一致。
- 新增内容不依赖外部图片或未提交资源。
- `mkdocs build --strict` 能够通过。
- 不提交与本任务无关的本地改动。
