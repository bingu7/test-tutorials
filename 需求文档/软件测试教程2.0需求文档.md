# 软件测试教程 2.0 需求文档

## 一、项目定位

软件测试教程 2.0 的目标不是继续堆更多教程，而是把现有内容升级成一个更适合零基础学习者的训练型教程站。

当前项目已经具备较完整的教程体系，覆盖测试理论、工具操作、专项测试、自动化测试、项目实战、模板库、案例库和面试专题。2.0 版本要重点补齐学习路径和反馈感，让用户不只是“看内容”，而是知道自己处在哪个阶段、该学什么、学到什么程度算过关、下一步应该去哪。

## 二、核心目标

1. 让用户进入网站后能快速判断自己的学习阶段。
2. 每个阶段都有明确目标、必学内容、练习任务和通关标准。
3. 每篇教程结束后给出下一步建议，减少用户迷路。
4. 用本地存储记录学习完成状态、练习完成状态和测验结果。
5. 让测验反馈从“显示分数”升级为“指出薄弱点并推荐复习内容”。
6. 保持当前 MkDocs Material 的简洁风格，不做复杂登录系统。

## 三、目标用户

### 1. 零基础学习者

特点：

- 不知道软件测试应该先学什么。
- 容易直接跳到自动化，忽略测试理论、SQL、Linux、接口基础。
- 需要明确的学习顺序和通关标准。

需要解决的问题：

- 先学什么。
- 每个阶段学到什么程度可以继续。
- 学完后能不能拿去面试表达。

### 2. 转岗或自学测试的人

特点：

- 有一些零散知识，但不成体系。
- 学过工具，但不知道项目里怎么使用。
- 需要项目实战和作品集输出。

需要解决的问题：

- 补齐薄弱环节。
- 把工具能力转成项目经验。
- 形成可展示的测试用例、测试报告和自动化报告。

### 3. 准备面试的人

特点：

- 已经学过一部分内容。
- 不知道如何表达项目经验。
- 缺少通关检查和模拟问答。

需要解决的问题：

- 判断自己哪些知识点还薄弱。
- 把学习成果整理成面试表达。
- 用项目作品证明自己不是只看过教程。

## 四、核心设计原则

1. 路径清楚：用户随时知道自己在哪一阶段。
2. 反馈明确：用户完成学习、练习或测验后能看到结果和下一步建议。
3. 轻量实现：优先使用 Markdown、CSS、JavaScript 和浏览器本地存储，不引入后端登录系统。
4. 新手友好：页面文字要具体，不写“正常”“正确”“继续学习”这种模糊提示。
5. 可持续扩展：后续可以逐步增加测验、练习、项目任务和作品集模板。

## 五、学习阶段设计

2.0 版本将学习路线拆成五个阶段。

| 阶段 | 名称 | 目标 |
|------|------|------|
| 第 1 阶段 | 测试入门 | 建立测试思维，理解测试流程、术语、用例设计和缺陷管理 |
| 第 2 阶段 | 工具实战 | 掌握 SQL、Linux、Git、Postman、Fiddler、网络知识等高频工具 |
| 第 3 阶段 | 专项测试 | 掌握接口测试、性能测试、安全测试等专项能力 |
| 第 4 阶段 | 自动化测试 | 掌握 Python 接口自动化、Selenium、Playwright、Appium |
| 第 5 阶段 | 项目与面试 | 完成项目实战，输出作品集材料，并能进行面试表达 |

每个阶段都需要包含：

- 阶段目标
- 适合人群
- 必学教程
- 推荐练习
- 阶段测验
- 通关标准
- 下一阶段入口

## 六、功能需求

### 1. 学习中心 2.0

学习中心需要从普通入口页升级成学习总控台。

页面应包含：

- 当前推荐路径
- 五个学习阶段卡片
- 每个阶段的完成度
- 当前推荐下一步
- 测验入口
- 项目实战入口
- 通关检查入口

示例信息：

```text
当前阶段：工具实战
完成度：3 / 8
下一步建议：学习 Postman 接口测试
提醒：建议先完成 SQL 基础测验，再进入接口自动化
```

交互要求：

- 用户可以勾选已学完的教程。
- 勾选状态保存在浏览器本地。
- 页面刷新后仍能恢复完成状态。
- 不要求账号登录和云端同步。

### 2. 阶段路线卡片

每个阶段在学习中心中展示为一张清晰卡片。

卡片内容：

- 阶段名称
- 一句话目标
- 必学数量
- 已完成数量
- 推荐学习时间
- 操作入口

示例：

```text
第 2 阶段：工具实战
目标：能用 SQL 查数据、用 Linux 看日志、用 Postman 调接口、用 Fiddler 抓包。
完成度：2 / 6
预计时间：10-14 天
入口：开始学习 / 通关检查
```

### 3. 教程底部下一步

每篇核心教程底部增加“下一步建议”模块。

模块内容：

- 你已经学完什么
- 学完后应该能做到什么
- 推荐下一篇教程
- 推荐练习
- 完成检查清单

示例：

```text
你已经学完：Docker 容器教程

完成检查：
- [ ] 我能解释镜像和容器的区别
- [ ] 我能启动一个服务
- [ ] 我能查看容器日志
- [ ] 我能停止并清理容器

下一步建议：
1. 如果你还不会 Linux，先学 Linux 实用教程。
2. 如果你已经会基础命令，进入 Jenkins CI/CD。
3. 如果你想做项目，进入 CI/CD 自动化回归实战。
```

交互要求：

- 完成检查项可勾选。
- 勾选状态保存在浏览器本地。
- 不影响 Markdown 原始内容阅读。

### 4. 阶段通关页

每个阶段需要一个通关检查页面，用来判断是否可以进入下一阶段。

页面内容：

- 阶段目标
- 必备能力清单
- 实操任务
- 测验入口
- 通关判断
- 下一阶段入口

示例：工具实战通关检查

```text
你需要能完成：
- [ ] 用 SQL 查询指定用户订单
- [ ] 用 Linux 查看最近 100 行错误日志
- [ ] 用 Postman 调试登录接口
- [ ] 用 Fiddler 找到登录请求
- [ ] 能判断问题属于前端、后端、数据还是网络

如果以上 80% 都能做到，可以进入专项测试。
```

### 5. 测验反馈增强

当前已有 Python 基础测验和 SQL 基础测验。2.0 需要把测验从“显示分数”升级为“给学习建议”。

反馈规则：

| 得分 | 反馈 |
|------|------|
| 60 分以下 | 建议回看基础教程，不建议进入下一阶段 |
| 60-79 分 | 可以继续学习，但需要补薄弱点 |
| 80 分及以上 | 当前阶段基础通过，可以进入下一步 |

测验提交后显示：

- 得分
- 正确数量
- 错误题目
- 薄弱知识点
- 推荐复习教程
- 下一步入口

示例：

```text
你答对 7 / 10
薄弱点：JOIN、GROUP BY、NULL 判断
建议回看：SQL 多表查询、聚合统计
下一步：Postman 接口测试
```

### 6. 本地学习进度存储

使用浏览器 localStorage 保存学习状态。

建议存储内容：

```json
{
  "learned": {
    "基础理论/软件测试理论基础教程": true,
    "工具操作/数据库SQL教程": true
  },
  "practice": {
    "docker-checklist": [0, 1, 2]
  },
  "quiz": {
    "python-basics": {
      "score": 80,
      "completedAt": "2026-06-12"
    }
  }
}
```

要求：

- 数据只保存在用户浏览器。
- 不需要注册登录。
- 清除浏览器缓存后数据可能丢失，需要在页面上适当提示。

### 7. 项目作品集入口

学习中心需要加入项目作品集入口，让用户知道学完后可以产出什么。

作品集材料包括：

- 测试计划
- 测试用例
- 缺陷报告
- 接口测试报告
- 自动化测试报告
- 项目总结
- 面试项目表达

项目实战页应强调：

```text
学完项目后，不只是知道怎么测，还要能输出一份可以复盘、可以面试表达的材料。
```

## 八、交互设计

### 1. 完成状态

交互形式：

- checkbox
- 完成数量
- 进度条
- 下一步推荐

状态示例：

```text
已完成 3 / 8
当前建议：继续学习 Postman 接口测试
```

### 2. 测验状态

交互形式：

- 提交答案
- 显示分数
- 标出正确和错误选项
- 展开解释
- 推荐复习内容

### 3. 下一步推荐

推荐逻辑优先级：

1. 如果当前阶段必学教程未完成，推荐下一篇必学教程。
2. 如果必学教程完成但测验未完成，推荐阶段测验。
3. 如果测验未达 80 分，推荐复习薄弱教程。
4. 如果阶段通过，推荐下一阶段或项目实战。

## 九、开发拆分

### 第一批：学习中心 2.0

目标：

- 改造学习中心为五阶段总控台。
- 展示阶段卡片、完成度和下一步建议。
- 使用 localStorage 保存完成状态。

验收标准：

- 用户可以勾选学习项。
- 刷新页面后状态保留。
- 阶段完成度能正确变化。
- 页面在桌面和移动端不乱。

### 第二批：阶段通关页

目标：

- 新增五个阶段通关检查页面。
- 每个页面包含能力清单、实操任务和下一步入口。

验收标准：

- 每个阶段通关页都有明确通关标准。
- 通关页能从学习中心进入。
- 勾选项状态可保存。

### 第三批：教程底部下一步

目标：

- 给核心教程底部增加下一步建议模块。
- 优先覆盖基础理论、SQL、Linux、Postman、接口测试、Python 自动化、Docker、Jenkins。

验收标准：

- 每篇教程末尾有清晰下一步。
- 检查项具体可执行。
- 链接全部可用。

### 第四批：测验反馈增强

目标：

- Python 和 SQL 测验提交后显示分数建议。
- 根据错题输出薄弱点和复习入口。

验收标准：

- 不同分数区间显示不同建议。
- 错题解释清楚。
- 推荐链接有效。

### 第五批：项目作品集入口

目标：

- 在学习中心和项目实战总览中强化作品集产出。
- 让用户知道每个项目完成后能得到什么材料。

验收标准：

- 项目实战页有作品集输出说明。
- 模板库和案例库能和项目实战关联起来。

## 十、非目标范围

2.0 第一阶段暂不做：

- 用户注册登录
- 云端同步学习进度
- 支付系统
- 评论区
- 复杂后台管理
- AI 批改作业
- 大规模题库系统

这些功能可以作为后续 3.0 或独立产品方向考虑。

## 十一、验收标准

2.0 初版完成后，应满足：

1. 用户进入学习中心后能看懂五阶段学习路径。
2. 用户能勾选学习项并看到完成度变化。
3. 用户知道当前阶段下一步应该学习什么。
4. 每个阶段都有通关标准。
5. 至少 Python 和 SQL 测验有反馈建议。
6. 核心教程底部有下一步建议。
7. 项目实战能明确引导用户输出作品集材料。
8. `python -m mkdocs build --strict` 构建通过。
9. 桌面端和移动端页面不出现明显布局错乱。

## 十二、优先级建议

最先做：

```text
学习中心 2.0 + 五阶段路线 + 本地完成状态
```

原因：

- 对用户感知最明显。
- 不需要大规模修改全部教程。
- 可以作为后续通关页、测验反馈、项目作品集的入口。

第二步做：

```text
阶段通关页 + 核心教程底部下一步
```

第三步做：

```text
测验反馈增强 + 项目作品集入口
```

这样可以边做边验证，不会一次性改太大。
