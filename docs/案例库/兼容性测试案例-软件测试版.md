# 兼容性测试案例

兼容性测试是验证应用在不同浏览器、不同操作系统、不同设备上是否能正常运行的测试。用户不会只用你推荐的浏览器，他们用什么你就得测什么。

## 需求背景

公司 Web 应用需要支持主流浏览器和操作系统。产品经理要求"用户用任何主流浏览器打开都能正常使用"。需要设计兼容性测试方案，覆盖主要浏览器和操作系统的组合。

## 测试矩阵

根据用户使用数据分析（Chrome 占 60%、Safari 占 15%、Edge 占 12%、Firefox 占 8%），确定测试优先级：

| 浏览器 | 版本 | Windows | macOS | 优先级 |
|--------|------|---------|-------|--------|
| Chrome | 最新稳定版 + 前一个版本 | ✅ | ✅ | P0 |
| Safari | 最新版本 | — | ✅ | P0 |
| Edge | 最新稳定版 | ✅ | ✅ | P1 |
| Firefox | 最新稳定版 | ✅ | ✅ | P1 |

移动端单独测试：

| 浏览器 | 设备 | 优先级 |
|--------|------|--------|
| Safari | iPhone（iOS 最新 + 前一版本） | P0 |
| Chrome | Android（主流机型） | P0 |

## 常见兼容性问题清单

### CSS 差异

| 问题 | 表现 | 浏览器 |
|------|------|--------|
| Flex 布局差异 | 子元素换行行为不同 | Safari 老版本 |
| Grid 布局支持 | 部分属性不支持 | IE11（已淘汰） |
| `gap` 属性 | Flex 下不支持 | Safari <14.1 |
| `backdrop-filter` | 毛玻璃效果不生效 | Firefox 老版本 |
| 滚动条样式 | `-webkit-scrollbar` 仅 Webkit 生效 | Firefox、Safari |
| 字体渲染 | 同一字体在不同系统下粗细不同 | macOS vs Windows |

### JS API 差异

| 问题 | 表现 | 浏览器 |
|------|------|--------|
| `Intl.DateTimeFormat` | 日期格式化结果不同 | Safari |
| `Clipboard API` | 需要用户手势触发 | Safari |
| `ResizeObserver` | 老版本不支持 | Safari <13.1 |
| `fetch` 超时处理 | 无原生 timeout 参数 | 所有浏览器 |
| `smooth` 滚动 | `scrollIntoView` 行为不同 | Safari |

### 响应式布局问题

| 问题 | 表现 |
|------|------|
| 未设置 viewport meta | 移动端缩放异常 |
| `vh` 单位 | 移动端浏览器地址栏影响 100vh 计算 |
| 图片未做响应式 | 小屏幕下图片溢出容器 |
| 文字过长溢出 | 未设置 `overflow` 和 `text-overflow` |

## 自动化兼容性测试方案

### 方案一：Selenium Grid（自建）

```
部署架构：
├── Selenium Hub（调度中心）
├── Windows Node（Chrome + Edge + Firefox）
└── macOS Node（Safari + Chrome）
```

优点：数据不出内网，可自定义环境。
缺点：维护成本高，需要自行管理多台机器。

### 方案二：BrowserStack / LambdaTest（云服务）

```
集成方式：
CI/CD Pipeline
  → Selenium 测试脚本
    → BrowserStack API（指定浏览器/OS 组合）
      → 云端虚拟机执行
        → 返回测试结果和截图
```

优点：无需自建环境，浏览器/设备组合齐全。
缺点：按量付费，网络延迟可能影响测试。

### 截图对比方案

```python
# 伪代码思路
for browser in ['chrome', 'firefox', 'safari', 'edge']:
    driver = get_driver(browser)
    driver.get('https://example.com')
    screenshot = driver.get_screenshot_as_png()
    compare_with_baseline(screenshot, browser)
```

关键点：
- 每个页面在每个浏览器下都要截图。
- 与基线截图做像素级对比，高亮差异区域。
- 关注布局偏移、颜色差异、元素缺失。

## 经验总结

1. **先确定测试矩阵**：不可能覆盖所有组合，要根据用户数据确定优先级。
2. **CSS 问题用 normalize.css**：统一浏览器默认样式，减少 80% 的兼容性问题。
3. **自动化截图对比比肉眼检查高效**：15 个页面 × 8 个浏览器 = 120 张截图，人工看会遗漏。
4. **Safari 是兼容性重灾区**：很多新 CSS/JS 特性 Safari 支持最慢。
5. **移动端 viewport 一定要设置**：不设置 viewport meta 标签会导致移动端显示异常。
6. **字体要有 fallback**：`font-family` 至少写 3 个备选字体。
