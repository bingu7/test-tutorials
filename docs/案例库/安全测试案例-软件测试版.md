# 安全测试案例

安全测试不是"找个工具扫一下"就完了。它需要理解攻击原理、设计攻击场景、验证防御措施是否生效。以下是电商系统安全测试的实战案例。

## 需求背景

电商系统上线前需要进行安全测试，重点关注 OWASP Top 10 中的高风险项。系统涉及用户个人信息、订单数据、支付流程，安全漏洞可能导致数据泄露和资金损失。

## 测试范围

聚焦 OWASP Top 10 中的 5 项重点：

| 编号 | OWASP 风险 | 测试内容 | 优先级 |
|------|------------|----------|--------|
| A01 | 访问控制失效 | 越权访问 | P0 |
| A03 | 注入 | SQL 注入 | P0 |
| A07 | XSS | 跨站脚本攻击 | P1 |
| A02 | 加密失败 | 敏感信息传输和存储 | P0 |
| A05 | 安全配置错误 | 响应头、错误信息泄露 | P1 |

## 越权测试案例

### 水平越权：A 用户访问 B 用户的订单

**攻击思路**：登录用户 A 的账号，尝试通过修改请求参数访问用户 B 的数据。

**测试步骤**：
1. 用用户 A 登录系统，访问自己的订单详情。
2. 捕获请求：`GET /api/orders/10001`（10001 是 A 的订单号）。
3. 修改订单号为 B 的订单号：`GET /api/orders/10002`。
4. 观察是否返回 B 的订单数据。

**预期结果**：返回 403 或"无权访问"，不能返回 B 的数据。

**缺陷示例**：

| 字段 | 内容 |
|------|------|
| 标题 | 水平越权：修改订单号可查看其他用户订单 |
| 前置条件 | 用户 A 已登录，订单 10002 属于用户 B |
| 复现步骤 | 用户 A 登录后，请求 `GET /api/orders/10002` |
| 实际结果 | 返回用户 B 的订单详情（含地址、手机号、商品信息） |
| 期望结果 | 返回 403，提示无权访问 |
| 影响 | 所有用户的订单数据可被任意用户查看，严重数据泄露 |

**修复建议**：后端校验订单所属用户，查询时加 `WHERE user_id = 当前登录用户ID` 条件。

### 垂直越权：普通用户访问管理员接口

**测试步骤**：
1. 用普通用户登录，获取 token。
2. 用该 token 请求管理员接口：`GET /api/admin/users`。
3. 观察是否返回用户列表。

**预期结果**：返回 403，不能访问管理员功能。

## SQL 注入测试案例

### 登录绕过

**攻击思路**：在登录表单中输入 SQL 注入 payload，绕过密码验证。

**测试步骤**：
1. 在用户名输入框输入：`admin' OR '1'='1' --`
2. 密码随意输入。
3. 点击登录。

**预期结果**：登录失败，不能绕过验证。

**缺陷示例**：

| 字段 | 内容 |
|------|------|
| 标题 | 登录接口存在 SQL 注入，可绕过密码验证 |
| 前置条件 | 登录接口未对输入做参数化处理 |
| 复现步骤 | 用户名输入 `admin' OR '1'='1' --`，密码随意，点击登录 |
| 实际结果 | 以 admin 身份登录成功 |
| 期望结果 | 登录失败，提示账号或密码错误 |
| 影响 | 攻击者可登录任意账号，无需知道密码 |

**修复建议**：
- 使用参数化查询（PreparedStatement），不要拼接 SQL。
- 对输入做严格校验：用户名只允许字母、数字、下划线。
- 部署 WAF（Web 应用防火墙）拦截常见注入 payload。

**其他注入测试点**：

| 测试点 | Payload 示例 |
|--------|-------------|
| 搜索框注入 | `' UNION SELECT username,password FROM users --` |
| 排序参数注入 | `ORDER BY (SELECT 1 FROM users WHERE username='admin')` |
| 批量查询注入 | `1; DROP TABLE orders --` |

## XSS 测试案例

### 评论区存储型 XSS

**攻击思路**：在评论内容中插入恶意 JavaScript 代码，其他用户浏览时自动执行。

**测试步骤**：
1. 在商品评论区提交内容：`<script>alert('XSS')</script>`
2. 刷新页面，查看评论是否被转义。
3. 用另一个账号访问该商品页面。

**预期结果**：脚本标签被转义为文本显示，不执行。

**缺陷示例**：

| 字段 | 内容 |
|------|------|
| 标题 | 评论区存在存储型 XSS 漏洞 |
| 前置条件 | 用户已登录，可提交评论 |
| 复现步骤 | 在评论区输入 `<script>alert(document.cookie)</script>` 并提交 |
| 实际结果 | 访问该商品页面时弹出 Cookie 内容 |
| 期望结果 | 脚本被转义为文本显示 |
| 影响 | 攻击者可窃取其他用户的 Cookie，劫持会话 |

**修复建议**：
- 输出时对 `<`、`>`、`"`、`'`、`&` 做 HTML 实体编码。
- 设置 CSP（Content-Security-Policy）响应头，限制脚本来源。
- 对用户输入做白名单过滤，只允许安全的 HTML 标签。

**其他 XSS 测试点**：

| 测试点 | Payload 示例 |
|--------|-------------|
| 用户昵称 | `<img src=x onerror=alert(1)>` |
| 收货地址 | `"><script>alert(1)</script>` |
| 搜索关键词 | `<svg onload=alert(1)>` |
| URL 参数 | `?search="><script>alert(1)</script>` |

## 敏感信息泄露案例

### 响应头泄露版本号

**测试步骤**：
1. 用浏览器开发者工具或 curl 查看响应头。
2. 检查 `Server`、`X-Powered-By` 等头信息。

**常见泄露**：
```
Server: nginx/1.18.0
X-Powered-By: Express
X-AspNet-Version: 4.0.30319
```

**影响**：攻击者可针对已知版本的漏洞进行精准攻击。

**修复建议**：移除或伪装版本信息头。

### 错误信息泄露堆栈

**测试步骤**：
1. 故意输入异常参数触发 500 错误。
2. 查看返回的错误信息是否包含堆栈、SQL 语句、文件路径。

**常见泄露**：
```json
{
  "error": "Internal Server Error",
  "detail": "com.mysql.jdbc.exceptions.jdbc4.MySQLSyntaxErrorException: Table 'prod_db.users' doesn't exist"
}
```

**影响**：泄露数据库类型、表名、代码结构，降低攻击门槛。

**修复建议**：生产环境返回通用错误信息，详细日志只写入服务器日志文件。

### 其他信息泄露检查点

| 检查项 | 方法 |
|--------|------|
| 前端注释 | 查看 HTML/JS 源码中的注释 |
| 接口文档 | 尝试访问 `/swagger-ui.html`、`/api-docs` |
| 目录遍历 | 尝试访问 `/backup/`、`/config/`、`/.env` |
| Git 泄露 | 尝试访问 `/.git/config` |
| 调试模式 | 尝试触发错误，看是否返回调试页面 |

## 经验总结

1. **安全测试要手动 + 工具结合**：自动化工具只能发现已知漏洞类型，逻辑漏洞需要手动测试。
2. **越权测试是最高频的安全漏洞**：很多系统只做了认证（你是谁），没做好授权（你能做什么）。
3. **SQL 注入用参数化查询就能解决**：不要试图用黑名单过滤来防御，总有绕过的方法。
4. **XSS 防御要在输出时编码**：输入时过滤不够，输出时 HTML 实体编码才是根本。
5. **错误信息要分环境**：开发环境可以详细，生产环境只能返回通用错误信息。
