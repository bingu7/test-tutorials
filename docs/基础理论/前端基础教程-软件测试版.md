# 前端基础教程（软件测试人员专用）

!!! abstract "教程简介"
    本教程面向软件测试工程师，讲解测试工作中需要了解的前端基础知识：HTML 结构、CSS 选择器、JavaScript 语法、浏览器调试工具。

## 新手导读

测试人员学前端，不是为了转前端开发，而是为了看懂页面结构、定位元素、判断问题发生在前端还是后端。

第一遍重点掌握：

1. HTML 标签表示页面结构。
2. CSS 选择器可以帮助自动化定位元素。
3. JavaScript 会触发页面交互和接口请求。
4. 浏览器开发者工具可以查看元素、网络请求和控制台错误。

学完后，你应该能打开浏览器 DevTools，找到按钮或输入框对应的 HTML，并能在 Network 面板里找到一次接口请求。

## 二、HTML 基础

### 2.1 什么是 HTML

HTML（HyperText Markup Language）是网页的骨架，用标签描述页面结构。

```html
<!DOCTYPE html>
<html>
<head>
    <title>页面标题</title>
</head>
<body>
    <h1>一级标题</h1>
    <p>这是一个段落。</p>
    <a href="https://example.com">链接</a>
    <img src="photo.jpg" alt="图片描述">
</body>
</html>
```

### 2.2 常用标签

| 标签 | 用途 | 示例 |
|------|------|------|
| `<div>` | 块级容器 | `<div class="header">...</div>` |
| `<span>` | 行内容器 | `<span class="error">错误信息</span>` |
| `<a>` | 链接 | `<a href="/login">登录</a>` |
| `<button>` | 按钮 | `<button id="submit">提交</button>` |
| `<input>` | 输入框 | `<input type="text" name="username">` |
| `<select>` | 下拉框 | `<select name="city">...</select>` |
| `<form>` | 表单 | `<form action="/api/login">...</form>` |
| `<table>` | 表格 | `<table><tr><td>单元格</td></tr></table>` |
| `<img>` | 图片 | `<img src="logo.png" alt="Logo">` |
| `<ul>` / `<ol>` | 列表 | `<ul><li>项目1</li></ul>` |
| `<h1>`-`<h6>` | 标题 | `<h1>一级标题</h1>` |
| `<p>` | 段落 | `<p>文本内容</p>` |

### 2.3 元素属性

属性是标签的附加信息，测试中最重要的是 `id`、`class`、`name`。

```html
<input 
    type="text"
    id="username"
    class="form-control"
    name="username"
    placeholder="请输入用户名"
    data-testid="login-input"
    value="testuser"
    disabled
>
```

| 属性 | 说明 |
|------|------|
| `type` | 输入类型 |
| `id` | 唯一标识（测试首选） |
| `class` | 样式类名（可多个） |
| `name` | 表单字段名 |
| `placeholder` | 占位符 |
| `data-testid` | 测试专用属性（推荐） |
| `value` | 值 |
| `disabled` | 禁用 |

**测试定位优先级：**

```
data-testid > id > name > class > 其他属性
```

### 2.4 表单元素

```html
<!-- 文本输入 -->
<input type="text" name="username">
<input type="password" name="password">
<input type="email" name="email">
<input type="number" name="age">
<input type="tel" name="phone">

<!-- 多行文本 -->
<textarea name="comment"></textarea>

<!-- 复选框 -->
<input type="checkbox" name="agree" value="yes">

<!-- 单选框 -->
<input type="radio" name="gender" value="male"> 男
<input type="radio" name="gender" value="female"> 女

<!-- 下拉框 -->
<select name="city">
    <option value="beijing">北京</option>
    <option value="shanghai">上海</option>
</select>

<!-- 文件上传 -->
<input type="file" name="avatar">

<!-- 隐藏字段 -->
<input type="hidden" name="token" value="abc123">

<!-- 按钮 -->
<button type="submit">提交</button>
<button type="button">普通按钮</button>
<input type="submit" value="提交">
```

### 2.5 iframe

iframe 是页面中嵌套的另一个页面：

```html
<iframe id="payment-frame" src="https://pay.example.com">
    <!-- 内部内容 -->
</iframe>
```

测试时需要切换到 iframe 内部才能操作元素。

### 2.6 Shadow DOM

Web Components 使用 Shadow DOM 封装内部结构：

```html
<my-component>
    #shadow-root
    <button id="btn">Click me</button>
</my-component>
```

Playwright 原生支持 Shadow DOM，Selenium 需要特殊处理。

## 三、CSS 选择器

CSS 选择器是 Selenium/Playwright 定位元素的基础。

### 3.1 基本选择器

| 选择器 | 含义 | 示例 |
|--------|------|------|
| `#id` | 按 ID | `#username` |
| `.class` | 按类名 | `.form-control` |
| `tag` | 按标签 | `button` |
| `tag.class` | 标签+类 | `button.btn-primary` |
| `tag#id` | 标签+ID | `input#username` |

### 3.2 属性选择器

| 选择器 | 含义 | 示例 |
|--------|------|------|
| `[attr]` | 有该属性 | `[disabled]` |
| `[attr="val"]` | 属性等于 | `[type="submit"]` |
| `[attr~="val"]` | 属性包含词 | `[class~="active"]` |
| `[attr^="val"]` | 属性以...开头 | `[href^="https"]` |
| `[attr$="val"]` | 属性以...结尾 | `[href$=".pdf"]` |
| `[attr*="val"]` | 属性包含 | `[href*="login"]` |

### 3.3 关系选择器

| 选择器 | 含义 | 示例 |
|--------|------|------|
| `A B` | A 的后代 B | `div p`（div 内所有 p） |
| `A > B` | A 的直接子 B | `ul > li` |
| `A + B` | A 紧邻的兄弟 B | `h1 + p` |
| `A ~ B` | A 后面的所有兄弟 B | `h1 ~ p` |

### 3.4 伪类选择器

| 选择器 | 含义 | 示例 |
|--------|------|------|
| `:first-child` | 第一个子元素 | `li:first-child` |
| `:last-child` | 最后一个子元素 | `li:last-child` |
| `:nth-child(n)` | 第 n 个子元素 | `tr:nth-child(2)` |
| `:not(selector)` | 排除 | `input:not([disabled])` |
| `:checked` | 选中的复选框 | `input:checked` |
| `:enabled` | 可用的 | `button:enabled` |
| `:focus` | 获得焦点的 | `input:focus` |

### 3.5 测试常用 CSS 选择器

```css
/* 登录按钮 */
#login-btn
button[type='submit']
.form-actions button.btn-primary

/* 错误消息 */
.error-message
.alert-danger
span.error

/* 表格第一行 */
table tbody tr:first-child

/* 导航菜单项 */
nav ul > li > a

/* 输入框 */
input[name='username']
input.form-control:not([disabled])
```

## 四、JavaScript 基础

### 4.1 为什么要了解 JS

- 理解前端逻辑（页面交互、接口调用）
- 在自动化中执行 JS（Playwright `page.evaluate()`）
- 看懂控制台报错
- 理解前端存储（Cookie、localStorage、sessionStorage）

### 4.2 基础语法

```javascript
// 变量
let name = "张三";        // 可变
const age = 25;           // 不可变
var old = "旧语法";        // 避免使用

// 数据类型
let str = "hello";        // 字符串
let num = 123;            // 数字
let bool = true;          // 布尔
let arr = [1, 2, 3];      // 数组
let obj = {name: "张三"};  // 对象
let nullVal = null;       // 空值
let undef;                // undefined

// 字符串
`hello ${name}`           // 模板字符串
"hello" + name            // 拼接
str.length                // 长度
str.includes("ell")       // 包含
str.replace("l", "L")     // 替换

// 数组
arr.push(4);              // 添加
arr.pop();                // 删除最后一个
arr.length;               // 长度
arr.includes(2);          // 包含
arr.map(x => x * 2);     // 映射
arr.filter(x => x > 1);  // 过滤

// 对象
obj.name                  // 访问
obj["name"]               // 等价
obj.age = 30;             // 修改/添加
```

### 4.3 函数

```javascript
// 普通函数
function greet(name) {
    return `你好, ${name}`;
}

// 箭头函数
const greet = (name) => `你好, ${name}`;

// 异步函数
async function getData() {
    const response = await fetch("/api/data");
    const data = await response.json();
    return data;
}
```

### 4.4 DOM 操作

```javascript
// 获取元素
document.getElementById("username")
document.querySelector(".form-control")           // 第一个匹配
document.querySelectorAll("input[type='text']")   // 所有匹配

// 操作元素
el.textContent = "新文本";
el.value = "新值";
el.style.display = "none";        // 隐藏
el.classList.add("active");       // 添加类
el.classList.remove("active");    // 删除类
el.setAttribute("disabled", "");  // 设置属性

// 事件
el.addEventListener("click", () => {
    console.log("被点击了");
});
```

### 4.5 浏览器存储

```javascript
// Cookie（每次请求自动携带）
document.cookie = "sessionId=abc123; path=/";
document.cookie                     // 读取所有

// localStorage（永久存储，除非手动清除）
localStorage.setItem("token", "eyJ...");
localStorage.getItem("token");
localStorage.removeItem("token");
localStorage.clear();

// sessionStorage（会话存储，关闭标签页清除，同源新标签页不共享）
sessionStorage.setItem("key", "value");
sessionStorage.getItem("key");
```

### 4.6 网络请求

```javascript
// fetch API
fetch("/api/user", {
    method: "POST",
    headers: {"Content-Type": "application/json"},
    body: JSON.stringify({name: "张三"})
})
.then(response => response.json())
.then(data => console.log(data));

// 异步版本
const response = await fetch("/api/user");
const data = await response.json();
```

## 六、测试场景实战

### 6.1 场景一：定位元素

**问题：** Selenium 找不到元素。

**排查：**

1. F12 → Elements 面板
2. Ctrl+F 搜索选择器
3. 检查元素是否在 iframe 中
4. 检查元素是否被 Shadow DOM 封装
5. 检查元素是否动态生成（需等待）

### 6.2 场景二：判断前端还是后端 Bug

**前端 Bug 特征：**

- 页面显示异常但接口数据正确
- 按钮点击无反应（JS 报错）
- 样式错乱
- 控制台有红色错误

**后端 Bug 特征：**

- 接口返回错误状态码
- 接口返回数据不正确
- 页面显示的是接口返回的错误信息

**排查步骤：**

1. F12 → Network 面板
2. 找到对应接口请求
3. 查看请求参数是否正确
4. 查看响应数据是否正确
5. 请求正确但显示异常 → 前端 Bug
6. 请求本身就有问题 → 后端 Bug

### 6.3 场景三：查看接口请求详情

1. F12 → Network → 筛选 XHR
2. 触发操作（如点击按钮）
3. 点击对应的请求
4. 查看：
   - **Headers**：请求方法、URL、请求头、Cookie
   - **Payload**：请求参数
   - **Preview/Response**：响应数据
   - **Timing**：耗时分析

### 6.4 场景四：修改页面元素

临时修改页面用于测试：

```javascript
// 在 Console 中执行

// 修改文本
document.querySelector(".price").textContent = "¥0.01";

// 修改按钮状态
document.querySelector("#submit").removeAttribute("disabled");

// 修改隐藏元素为可见
document.querySelector(".hidden-panel").style.display = "block";

// 模拟登录态
localStorage.setItem("token", "test-token-123");
```

### 6.5 场景五：抓取动态加载的数据

1. F12 → Network → 筛选 XHR
2. 刷新页面或触发操作
3. 找到数据接口
4. 查看请求参数和响应格式
5. 在 Postman 中重建该请求

## 七、常见问题排查

### 7.1 元素找不到

- 检查是否在 iframe 中
- 检查是否是动态生成的（需等待）
- 检查是否有 Shadow DOM
- 用 `document.querySelectorAll()` 在控制台验证选择器

### 7.2 控制台报错

常见错误：

| 错误 | 含义 |
|------|------|
| `Uncaught TypeError` | 类型错误（如调用 undefined 的方法） |
| `Uncaught ReferenceError` | 变量未定义 |
| `CORS error` | 跨域请求被阻止 |
| `404 Not Found` | 资源不存在 |
| `500 Internal Server Error` | 服务器错误 |

### 7.3 接口请求看不到

- 确认 Network 面板是否在录制（红色圆点）
- 检查是否被筛选条件排除
- 检查是否是 WebSocket 请求（WS 标签）
- 检查是否在 Service Worker 中

### 7.4 页面加载慢

1. Network 面板查看瀑布图
2. 找到耗时最长的请求
3. 检查是否是大文件（图片、JS）
4. 检查是否是接口响应慢
5. 检查是否有阻塞渲染的资源

## 动手任务：用 DevTools 定位「结算按钮点不动」的根因并定性

> 这是本教程的收尾练习。请**独立完成**，不要先看参考答案。目标不是"会按 F12"，而是**能拿证据说清"坏在哪一层"——前端渲染/样式/脚本，还是后端返回的数据**。

### 任务背景

测试同学提了一个 Bug：「订单详情页，点『去结算』按钮没反应，页面上一直转圈。」

开发回了一句「我本地好好的，应该是你们数据的问题」。你需要在不改代码的前提下，用浏览器 DevTools 把这件事查清楚，并给出**可复现、可举证**的结论。

### 任务数据

页面关键结构如下（为便于练习，这里给出等价的最小 HTML，你可以直接保存为 `checkout.html` 用浏览器打开复现）：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=375, initial-scale=1">
    <title>订单详情</title>
    <style>
        #app { padding: 12px; }
        .btn-primary { padding: 8px 16px; }
        /* 遮罩层：请求数据时显示，用于禁止用户重复点击 */
        .loading-mask {
            position: fixed;
            inset: 0;
            background: rgba(0, 0, 0, .4);
            z-index: 9999;
            display: block;   /* 期望是 none —— 请求结束后应由 JS 移除 */
        }
    </style>
</head>
<body>
    <div id="app">
        <div class="order-amount">应付金额：<span class="price">¥258.00</span></div>
        <form id="order-form" action="/order/confirm">
            <button id="checkout-btn" class="btn btn-primary" type="submit"
                    data-testid="checkout-btn">去结算</button>
        </form>
    </div>

    <!-- 加载遮罩 -->
    <div class="loading-mask"><span class="loading-text">加载中...</span></div>

    <script>
        // 期望：数据请求结束后把遮罩隐藏、并给按钮绑定跳转
        // 实际：这段脚本在 min.js 里报错中断了，遮罩被永久留下
        document.getElementById("checkout-btn").addEventListener("click", () => {
            window.location.href = "/order/confirm";
        });
    </script>
</body>
</html>
```

后端接口 `GET /api/order/detail?orderId=SO20260601001` 的真实响应（从 Network 面板复制，节选）：

```json
{
    "code": 0,
    "msg": "success",
    "data": {
        "orderId": "SO20260601001",
        "status": 2,
        "totalAmount": 258.0,
        "payAmount": 258.0,
        "items": [
            { "sku": "SKU-A1", "qty": 2, "price": 99.0 },
            { "sku": "SKU-B2", "qty": 1, "price": 60.0 }
        ]
    }
}
```

### 任务要求

请依次完成，并**保留每条命令和输出**（DevTools 里的操作写成「做了什么 → 看到什么」）：

1. **确认现象并缩小范围**：打开页面，用 Elements 面板确认按钮是否存在、`#checkout-btn` 的盒子尺寸是多少。把答案写清楚：**按钮"在不在"** 和 **按钮"能不能被点到"** 是两件事。
2. **用 Console 验证选择器**：在 Console 里依次执行下面 4 个表达式，记录每个的返回值，并解释**为什么不能只看第一个就把元素当作"可用"**：

   ```javascript
   document.querySelectorAll("#checkout-btn").length
   document.querySelectorAll(".btn-primary").length
   document.querySelectorAll("button[type='submit']").length
   document.querySelectorAll(".loading-mask").length
   ```

3. **定位"点不动"的根因**：说明当你在 Elements 里右键按钮 → **Force state → :hover**，或在 Console 里执行 `document.elementFromPoint(x, y)`（x、y 取按钮中心点坐标）时会得到什么元素。据此给出根因。
4. **判断这是前端缺陷还是后端数据问题**：把接口响应数据与页面显示逐项对照（金额、订单号、明细），给出**结论 + 依据**，并指出应该把 Bug 单派给哪个角色。
5. **可复用产出**：写出一段可在 Console 直接粘贴运行的 JavaScript，输入一个 CSS 选择器，输出该元素的「是否存在 / 尺寸 / 是否被更高层元素遮挡」三项判定。

### 完成标准

- [ ] 对"点不动"的结论有**具体证据**（遮挡元素的 class 与 z-index、或 `elementFromPoint` 返回的元素），而不是"猜是前端的问题"

??? tip "参考答案与思路（先自己做完再看）"

    **第 1 题：按钮"在不在" ≠ 按钮"能不能点"**

    `button` 元素确实存在，`type="submit"`，`data-testid="checkout-btn"`，没有 `disabled`。它的渲染盒子也不是 0：

    ```
    元素：<button id="checkout-btn" class="btn btn-primary" type="submit" data-testid="checkout-btn">去结算</button>
    getBoundingClientRect() -> { width: 80, height: 32, ... }   // 示例值：随字体/缩放变化，以你实际取到的为准
    ```

    判定标准是**宽高都大于 0**，而不是等于某个具体数字：

    ```javascript
    const r = document.querySelector("#checkout-btn").getBoundingClientRect();
    r.width > 0 && r.height > 0;    // true —— 元素有可见的盒子
    ```

    只要不为 0，元素就会被画出来。但"存在 + 有尺寸"只说明它会被画出来；**能不能被点到，还取决于它在那个坐标上是不是"最上层"的元素**——这是本任务的关键。

    另外要在 Elements 面板确认它是**直接子元素**，没有落在 `iframe` 或 `#shadow-root` 里（本例没有），否则 `document.querySelector` 根本查不到它。

    **第 2 题：选择器验证结果**

    | 表达式 | 返回值 | 说明 |
    |--------|--------|------|
    | `querySelectorAll("#checkout-btn").length` | `1` | id 唯一，能找到 |
    | `querySelectorAll(".btn-primary").length` | `1` | 类名能找到（注意：类名可能被多个元素共用，不能当唯一标识） |
    | `querySelectorAll("button[type='submit']").length` | `1` | 属性选择器能找到 |
    | `querySelectorAll(".loading-mask").length` | `1` | **关键线索：遮罩层仍在 DOM 里** |

    为什么不能只看第一个：`querySelectorAll("#checkout-btn").length === 1` 只证明**元素存在**。自动化脚本（Selenium/Playwright）"找得到元素但点击报 `Element is not clickable / intercepted`"，根因正是"存在但被遮挡"。所以定位前必须同时验证元素的**可见性与可点击性**。

    **第 3 题：根因是遮罩层遮挡**

    取按钮中心点坐标，在 Console 执行：

    ```javascript
    const el = document.querySelector("#checkout-btn");
    const r = el.getBoundingClientRect();
    const cx = (r.left + r.right) / 2;
    const cy = (r.top + r.bottom) / 2;
    const top = document.elementFromPoint(cx, cy);
    top.className;      // "loading-mask"  ← 命中测试打到的不是按钮！
    ```

    `elementFromPoint` 返回的是 `.loading-mask` 而不是 `#checkout-btn`，说明**命中测试（hit-testing）打到了遮罩层**——按钮"点不动"不是因为它坏了，而是因为它上面盖了一层东西。

    根因链：

    1. `.loading-mask` 用了 `position: fixed; inset: 0; z-index: 9999`，**铺满整个视口且层级最高**。
    2. 它本应在接口返回后被 JS 移除（`display: none` 或 `.remove()`）。
    3. 页面脚本在"隐藏遮罩"之前抛错中断（Console 里能看到 `Uncaught` 红字），于是遮罩被**永久留在页面上**，把所有点击都吃掉了。

    注意遮罩背景是 `rgba(0, 0, 0, .4)` 半透明，肉眼可能只看到页面变暗，容易误判成"页面卡住了"。

    > 反面排查：如果 Console 里 `elementFromPoint` 返回的就是 `#checkout-btn`，那问题不在遮挡，要去查事件监听是否绑定成功、`<form>` 的 `action` 是否被拦截等。

    **第 4 题：定性——前端缺陷，不是后端数据问题**

    逐字段对照：

    | 页面显示 | 接口返回 | 是否一致 |
    |----------|----------|----------|
    | 应付金额 ¥258.00 | `payAmount: 258.0` | ✅ 一致 |
    | 订单号 SO20260601001 | `orderId: "SO20260601001"` | ✅ 一致 |
    | 明细：2 件商品 | `items` 数组长度 2 | ✅ 一致 |
    | 无错误提示 | `code: 0`、`msg: "success"` | ✅ 正常 |

    **接口返回正确 + 页面渲染正确 + 只是点击被拦 → 前端缺陷**（属于 CSS/JS 缺陷：遮罩未正确关闭 + 脚本报错）。应把 Bug 单派给**前端开发**，并在单里附上：`elementFromPoint` 的返回值、`.loading-mask` 的 `z-index`、Console 的报错栈。

    如果接口返回的 `payAmount` 本身错了（比如返回 `89.0`），那才是后端问题，页面只是"如实展示了错误数据"。**判断口诀：接口对、页面不对 → 前端；接口就不对 → 后端。**

    **第 5 题：可复用的 Console 判定脚本**

    ```javascript
    /**
     * 判定一个元素"是否可用"：存在 / 有尺寸 / 未被更高层元素遮挡。
     * 用法：checkClickable("#checkout-btn")
     */
    function checkClickable(selector) {
        const el = document.querySelector(selector);
        if (!el) {
            return { selector, exists: false, reason: "元素不存在" };
        }

        const r = el.getBoundingClientRect();
        if (r.width === 0 || r.height === 0) {
            return { selector, exists: true, visible: false, reason: "尺寸为 0，不可点击" };
        }

        const cx = (r.left + r.right) / 2;
        const cy = (r.top + r.bottom) / 2;
        const topEl = document.elementFromPoint(cx, cy);

        // 命中的可能是按钮的子元素（如 <span>），要向上找
        const hitSelf = topEl === el || el.contains(topEl);
        return {
            selector,
            exists: true,
            visible: true,
            size: { width: r.width, height: r.height },
            center: { x: cx, y: cy },
            clickable: hitSelf,
            reason: hitSelf
                ? "中心点命中的就是本元素，可点击"
                : `中心点被 .${topEl.className}（<${topEl.tagName.toLowerCase()}>）遮挡`,
        };
    }

    // 实测（示例值，尺寸随字体变化）：
    checkClickable("#checkout-btn");
    // -> { exists: true, visible: true, size: {width:80,height:32}, clickable: false,
    //      reason: "中心点被 .loading-mask（<div>）遮挡" }

    checkClickable("#not-exist");
    // -> { exists: false, reason: "元素不存在" }
    ```

    修好之后（把遮罩设为 `display: none` 或从 DOM 移除），再跑一次 `checkClickable("#checkout-btn")`，`clickable` 应变为 `true`——**这就是"修复前 / 修复后"的可验证对照**。
