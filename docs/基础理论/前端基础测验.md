## 选择题

<div class="quiz-container" data-quiz-id="frontend-basics">

<div class="quiz-item" data-correct="1">
<div class="quiz-question">CSS 选择器中，<code>#login-btn</code> 与 <code>.login-btn</code> 的区别是？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q1" value="0"> <code>#</code> 匹配 class，<code>.</code> 匹配 id</label>
<label class="quiz-option"><input type="radio" name="q1" value="1"> <code>#</code> 匹配 id，<code>.</code> 匹配 class</label>
<label class="quiz-option"><input type="radio" name="q1" value="2"> 两者都匹配标签名，只是写法不同</label>
<label class="quiz-option"><input type="radio" name="q1" value="3"> <code>#</code> 匹配后代元素，<code>.</code> 匹配同级元素</label>
</div>
<div class="quiz-explanation">💡 <code>#id</code> 定位唯一元素，<code>.class</code> 定位一类元素。写自动化脚本时优先用 id 或 data 属性；用 class 定位要确认它在页面上是否唯一，否则会取到错误的元素</div>
</div>

<div class="quiz-item" data-correct="3">
<div class="quiz-question">元素定位失败，排查时发现目标元素在 <code>&lt;iframe&gt;</code> 内。正确的处理方式是？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q2" value="0"> 延长等待时间，等 iframe 加载完成即可</label>
<label class="quiz-option"><input type="radio" name="q2" value="1"> 改用绝对 XPath 从根节点一路写下来</label>
<label class="quiz-option"><input type="radio" name="q2" value="2"> 刷新页面后重新定位</label>
<label class="quiz-option"><input type="radio" name="q2" value="3"> 先切换到该 iframe，定位完成后再切回主文档</label>
</div>
<div class="quiz-explanation">💡 iframe 内部是一份独立的文档，主文档的定位上下文看不到里面的元素。必须先 <code>switch_to.frame()</code> 进入，操作完再 <code>switch_to.default_content()</code> 回到主文档</div>
</div>

<div class="quiz-item" data-correct="0">
<div class="quiz-question">用页面源码复制到的 XPath 始终定位不到元素，最可能的原因是？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q3" value="0"> 元素由 JS 动态生成，源码里并不存在</label>
<label class="quiz-option"><input type="radio" name="q3" value="1"> XPath 语法在浏览器里不被支持</label>
<label class="quiz-option"><input type="radio" name="q3" value="2"> 浏览器的渲染引擎与脚本不一致</label>
<label class="quiz-option"><input type="radio" name="q3" value="3"> 页面必须有登录态才能解析 XPath</label>
</div>
<div class="quiz-explanation">💡 DevTools 的 Elements 面板展示的是<strong>当前已渲染</strong>的 DOM，包含 JS 插入的节点；而"查看网页源代码"拿到的是最初返回的 HTML。现代前端应用大量依赖动态渲染，所以只能以 Elements 面板为准</div>
</div>

<div class="quiz-item" data-correct="2">
<div class="quiz-question">页面显示样式错乱，但 Network 面板里对应接口返回的数据完全正确。这属于？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q4" value="0"> 后端 Bug，因为数据来自后端</label>
<label class="quiz-option"><input type="radio" name="q4" value="1"> 环境问题，与前后端都无关</label>
<label class="quiz-option"><input type="radio" name="q4" value="2"> 前端 Bug，接口没问题但渲染结果不对</label>
<label class="quiz-option"><input type="radio" name="q4" value="3"> 无法判断，必须等开发排查</label>
</div>
<div class="quiz-explanation">💡 定界逻辑很简单：请求参数正确、响应内容正确、页面表现错误 → 问题出在前端渲染或 JS 逻辑。反之，请求本身就不对或返回错误，才是后端问题。先看 Network 再提缺陷，能显著减少被开发打回</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">点击按钮后接口报了 500，但你在 Network 面板里怎么都找不到这条请求。最合理的下一步是？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q5" value="0"> 直接判定为后端没有收到请求</label>
<label class="quiz-option"><input type="radio" name="q5" value="1"> 打开 Preserve log（保留日志），再重新触发一次操作</label>
<label class="quiz-option"><input type="radio" name="q5" value="2"> 切换到 Console 面板查看元素结构</label>
<label class="quiz-option"><input type="radio" name="q5" value="3"> 清空浏览器缓存后重启浏览器</label>
</div>
<div class="quiz-explanation">💡 Network 面板默认在页面跳转时清空记录，很多"看不到请求"都是因为请求发生在跳转前或跳转瞬间。勾选 Preserve log 后重新触发，就能把完整链路的请求保留下来</div>
</div>

<div class="quiz-item" data-correct="3">
<div class="quiz-question">在 Console 中执行 <code>localStorage.setItem("token", "test-token-123")</code> 的目的是？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q6" value="0"> 永久修改服务端的登录态数据</label>
<label class="quiz-option"><input type="radio" name="q6" value="1"> 加密浏览器与服务端的通信内容</label>
<label class="quiz-option"><input type="radio" name="q6" value="2"> 清除本地缓存的登录信息</label>
<label class="quiz-option"><input type="radio" name="q6" value="3"> 在本地构造登录态，跳过登录直接测后续页面</label>
</div>
<div class="quiz-explanation">💡 前端存储只在本地生效，适合快速搭建测试前置条件。但要清楚它只改了浏览器这一侧——如果服务端会校验 token 有效性，伪造的 token 依旧会被拒绝，这也是一个值得验证的点</div>
</div>

<div class="quiz-item" data-correct="0">
<div class="quiz-question">在 Elements 面板把商品价格从 ¥199 改成 ¥0.01，这个操作的影响是？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q7" value="0"> 只改变当前页面的显示，不影响后端数据</label>
<label class="quiz-option"><input type="radio" name="q7" value="1"> 会同步修改数据库里的商品价格</label>
<label class="quiz-option"><input type="radio" name="q7" value="2"> 会触发一次价格更新接口</label>
<label class="quiz-option"><input type="radio" name="q7" value="3"> 刷新页面后修改依然保留</label>
</div>
<div class="quiz-explanation">💡 改 DOM 只是改了浏览器内存里的渲染结果，刷新即失效，服务端毫不知情。它的价值在于快速验证"如果是这个值，后续逻辑还会不会出问题"，比如测试前端金额格式化、优惠计算显示</div>
</div>

<div class="quiz-item" data-correct="2">
<div class="quiz-question">关于 localStorage、sessionStorage 和 Cookie，下列说法正确的是？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q8" value="0"> 三者都会随每个请求自动发送到服务端</label>
<label class="quiz-option"><input type="radio" name="q8" value="1"> 三者关闭浏览器后都会立即清空</label>
<label class="quiz-option"><input type="radio" name="q8" value="2"> localStorage 长期保存，sessionStorage 随标签页关闭清空，Cookie 会自动随请求发送</label>
<label class="quiz-option"><input type="radio" name="q8" value="3"> 三者的存储容量完全相同</label>
</div>
<div class="quiz-explanation">💡 测试登录态"记住我"、多标签页互踢、退出登录是否清理本地信息时，都要先搞清楚数据存在哪里。Cookie 会自动带上请求头，这也是 CSRF 风险的来源之一</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">想快速确认某个"加入购物车"按钮背后的真实接口和参数，最高效的做法是？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q9" value="0"> 直接去问开发要接口文档</label>
<label class="quiz-option"><input type="radio" name="q9" value="1"> Network 面板筛选 XHR，点击按钮后查看该请求的 Headers 和 Payload</label>
<label class="quiz-option"><input type="radio" name="q9" value="2"> 在 Console 里打印页面所有 DOM 节点</label>
<label class="quiz-option"><input type="radio" name="q9" value="3"> 用抓包工具对整站流量做全量嗅探</label>
</div>
<div class="quiz-explanation">💡 XHR 筛选配合"点一下看一条"是最快的路径，拿到请求地址、参数、鉴权头和响应后，还能直接在 Postman 中重建，为接口测试和自动化打基础</div>
</div>

<div class="quiz-item" data-correct="3">
<div class="quiz-question">浏览器控制台出现红色报错，作为测试人员合理的处理是？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q10" value="0"> 忽略，控制台报错只对开发有意义</label>
<label class="quiz-option"><input type="radio" name="q10" value="1"> 把报错原文当作缺陷标题直接提交</label>
<label class="quiz-option"><input type="radio" name="q10" value="2"> 立刻重启浏览器确认是否为环境问题</label>
<label class="quiz-option"><input type="radio" name="q10" value="3"> 结合复现步骤记录报错内容，作为缺陷定位线索写进报告</label>
</div>
<div class="quiz-explanation">💡 控制台报错往往直接指出 JS 异常的堆栈和文件位置，是非常有价值的定位线索。把它连同复现步骤、截图一起写进缺陷报告，能明显缩短开发的定位时间</div>
</div>

<div class="quiz-item" data-correct="0">
<div class="quiz-question">页面首屏加载很慢，想定位"慢在哪一段"，应该重点看 Network 面板的哪个信息？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q11" value="0"> 各请求的 Timing（耗时）分布和瀑布流</label>
<label class="quiz-option"><input type="radio" name="q11" value="1"> 请求的总数量</label>
<label class="quiz-option"><input type="radio" name="q11" value="2"> 响应的 Content-Type</label>
<label class="quiz-option"><input type="radio" name="q11" value="3"> 请求的 User-Agent</label>
</div>
<div class="quiz-explanation">💡 Timing 会把一次请求拆成排队、DNS、连接、TLS、等待响应、内容下载等阶段，瀑布图还能看出串行依赖。它能直接指出瓶颈是网络、服务端处理还是资源体积</div>
</div>

<div class="quiz-item" data-correct="2">
<div class="quiz-question">测试人员学前端基础，最核心的价值是？</div>

</div>
