### 新增
- **6 项教程缺口补齐（9 篇新内容）**：依据真实招聘 JD 调研，补齐站点此前完全缺失的能力项
  - **`工具操作/禅道与Jira实战教程-软件测试版.md` + 测验**：缺陷全生命周期流转（激活 → 已解决 → 关闭 / 重新激活）、用例管理、严重程度与优先级的区别（破坏力 vs 紧急度）、解决结果分支处理、JQL 常用查询、Git 智能提交集成、缺陷重开率与收敛趋势等质量度量。此前站点只在基础理论里用三行表格提过工具名，**没有任何操作教学**——而这是功能测试 JD 中出现频率最高的工具要求

  - **`面试专题/简历撰写与项目包装.md`**：技能三段式写法（掌握程度 + 具体能力 + 应用结果）、项目"背景 → 职责 → 动作 → 结果"公式、量化要点、造假风险、简历自查清单
  - **`面试专题/岗位JD对照与投递策略.md`**：三步读 JD、硬性门槛与加分项的区分、技能矩阵对照打分、按 JD 调整简历三处、内推话术、投递批次节奏、外包识别
  - **`面试专题/面试流程与谈薪.md`**：各轮考察重点、自我介绍三段式、反问清单、薪资结构必问项、报价区间策略、offer 对比维度、背调与入职材料。此前站点教了"怎么答"，但投递/内推/offer/背调全站零覆盖，「学完 → 面试」链路是断的
- **`项目实战/练习靶场与工具清单.md`**：7 个公开靶场逐一实测（含各靶场特点与已知坑）、配套具体练习任务、靶场可用性自检脚本。解决"没有可测对象"的问题，并指向独立维护的自建 Mock 服务仓库 [test-lab-api](https://github.com/bingu7/test-lab-api)
- **JMeter 教程第十四章扩写（14.6-14.13）**：新增完整瓶颈定位工具链 —— 四层定位法（压测机 → 应用 → 数据库 → 系统/中间件）、慢查询采集与 EXPLAIN 执行计划解读、索引失效场景、连接池与锁等待、JVM 层（jstat GC 判读、jstack 线程 dump、jmap 堆分析）、Arthas 在线诊断（trace/profiler）、中间件定位（Redis 大 key 与热 key、MQ 堆积、Nginx 502/504），并以一个"TPS 上不去"的完整排查案例串起全流程
- **AI 辅助测试教程内容更新至当前实践**：新增 **MCP（Model Context Protocol）接入**一节（含只读权限、操作审计、危险操作人工确认三条底线）、**OWASP LLM Top 10** 测试大纲（10 条风险逐条给出测试关注点，并点明"LLM05 输出处理不当"最易被忽略、危害最大）、**Playwright 官方三个 Test Agent**（planner / generator / healer，含 `init-agents` 初始化与串成闭环的用法，并强调 healer 修复结果必须人工复核，防止把真实缺陷"修"成通过）；同时把「2025 年行业趋势」改为「行业现状」，补上 MCP 成为连接标准、官方 Agent 落地、模型能力趋同三个变化。配套测验由 12 题扩到 16 题，覆盖 MCP、OWASP、Playwright Agents 与 Prompt 注入断言方法
- **`_check_table_html.py` 内容门禁**：校验两类会破坏页面结构的表格问题 —— ① 表格单元格里的**裸 HTML 标签**（如未转义的 `<script>` 会被浏览器当成真标签，进入 script 解析状态后吞掉后续所有内容含页脚，表现为页脚浮在表格上、右侧列被截断）；② 表格行**空首列**（`|| A |` 会让内容整体右移一列）。已接入 CI，并做了误报规避（跳过代码块内的 `|| true`、允许模板里的全空行）
- **「练习总览」页**：集中展示全部可自动判分的在线练习（题目、所属教程、阶段、检查项数），表格读取本机练习记录并实时显示状态（未做 / `N/M` 部分通过 / ✅ 已通过），顶部给出「已通过 N/M 道」汇总。数据口径说明：**只收录答案有客观对错的题**；39 篇教程里的判断力型任务（缺陷定性、方案取舍等）保持开放式，因为用选择题判分会让学习退化成背答案——页面上有独立说明，避免读者误以为题目缺失
- **练习框「看提示」按钮**：不必先答错就能主动查看提示，按检查项逐条给出方向性提示（不给答案），可展开/收起
- **练习全通过后自动标记教程为「已学习」**：做完练习比手动勾选框更能证明掌握，因此全部断言通过时会自动勾选当前教程的完成状态并同步页面按钮；已有勾选不重复写入，用户手动取消后也不会被"再跑一次练习"强行加回
- **在线练习结果接入学习进度**：练习判分结果写入 `learning-progress-2.0`（`labs` 字段），与教程勾选、阶段测验**分开记账**——测验考"记没记住"，练习考"会不会做"。三条关键规则：**只有全部断言通过才算完成**（避免"跑一次拿到 4/5"就刷满进度）、**一旦通过不回退**（后续重跑失败不回扣进度）、未通过的不计入阶段完成度。阶段进度分母同步纳入练习，进度面板新增练习标签（通过显示 ✅、未满分显示 `N/M`），总体概览改为「教程 x/y · 测验 x/y · 练习 x/y」三段式
- **4 个在线练习**：Python 基础的「用例结果统计」、正则表达式的「日志字段提取」、JMeter 的「性能指标换算」、练习场热身题；每项 4-5 条断言，参考答案与全部数字均已实际跑通验证。其中性能练习刻意加了「换一组数据仍能正确判断不达标」的断言，专门防止对当前数据写死答案
- **动手任务在线判分（Pyodide 沙箱）**：教程里的动手任务现在可以**在页内直接写代码并自动判分**。运行 Python 3 完全在浏览器内完成，**不依赖任何后端服务**，库文件本地托管（`docs/javascripts/vendor/pyodide/`，v0.26.2，约 13 MB）并**懒加载**——只有进入含练习的页面才下载，且被浏览器缓存，不影响教程页首屏。判分方式是**执行学生代码后用断言检查结果**，而不是字符串比对，所以实现逻辑对了就能通过，不要求变量名与参考答案一致；支持任务预置数据（`prelude`）、代码自动保存（localStorage）、按项反馈 + 提示、运行超时保护

- **两个门禁改为「显式登记 + 完整性反查」，消除静默漏检**：
  1. `_check_counts.py` 原先用硬编码文件名集合给 `docs/` 根目录页面分类，未登记的新页面会**静默掉出所有分类**，只留一句含糊的「合计不符」。现改为 `ROOT_CATEGORY` 显式登记：出现未登记文件、或登记了不存在的文件，都会**指名报错并失败**。本次新增「练习总览」时该门禁确实拦住了未同步的四处口径，暴露了这个设计缺陷。
  2. `_check_labs.py` 原先用「lab id 前缀猜」的方式筛选引用（`py-`/`regex-`/…），前缀不同的新练习会被**静默跳过**（等于没检查）。现改为解析各阶段的 `labs: [...]` 数组，并新增**反向检查**：阶段教程页面上的练习若未注册到该阶段，直接报错——否则练习做了却不计入阶段进度，且界面上看不出任何异常。
  修这两个点时又发现**我自己新写的反向检查有 bug**：`seen_ids[lid]` 存的是字符串（页面名），却被当列表迭代，导致整个检查恒真通过——正是「看起来绿、实际什么都没查」的典型。已修正并用两个场景（摘掉注册 / 注册不存在的 id）验证门禁真的会失败。

## 版本说明

### 版本号规则

- **主版本号（MAJOR）**：不兼容的 API 修改
- **次版本号（MINOR）**：向下兼容的功能性新增
- **修订号（PATCH）**：向下兼容的问题修正

### 变更类型

- **新增（Added）**：新功能
- **变更（Changed）**：对现有功能的变更
- **弃用（Deprecated）**：即将移除的功能
- **移除（Removed）**：已移除的功能
- **修复（Fixed）**：任何 bug 修复
- **安全（Security）**：安全相关的变更

### 更新频率

- **主版本**：每季度发布一次（重大更新）
- **次版本**：每月发布一次（新功能）
- **修订版本**：每周发布（bug 修复和小改进）

### 如何获取更新

1. **GitHub 仓库**：Watch 仓库获取更新通知
2. **在线文档**：访问 [https://bingu7.github.io/test-tutorials/](https://bingu7.github.io/test-tutorials/)
3. **RSS 订阅**：订阅文档更新（如果支持）

4. 等待审核和合并
