# 学习验收与通关路径

!!! abstract "新手导读"
    这份通关路径用于把学习过程变成可验收的训练任务。学完不等于掌握，能独立完成任务、输出证据、讲清思路，才算真正过关。

---

## 使用方式

| 步骤 | 说明 |
|------|------|
| 选择阶段 | 从当前能力匹配的阶段开始，不必跳到最高阶段 |
| 完成任务 | 每个阶段都要有可提交的文档、脚本、截图或报告 |
| 自我评分 | 按通关标准打分，低于 80 分继续补练 |
| 复盘补缺 | 写下不会的点，回到对应教程重学 |

建议把每个阶段产出放到自己的学习仓库或笔记目录中。

---

## 一、五阶段学习路径

```text
第 1 阶段：测试入门
    ↓
第 2 阶段：工具实战
    ↓
第 3 阶段：专项测试
    ↓
第 4 阶段：自动化测试
    ↓
第 5 阶段：项目与面试
```

每一阶段都包含：

- 学习目标
- 必学教程
- 通关任务
- 验收标准
- 常见扣分点

## 二、第 1 阶段：测试入门

**建议学时：2-3 周**

### 学习目标

- 理解软件测试目的、流程和常见分类。
- 能拆测试点。
- 能写基础测试用例。
- 能提交清晰缺陷。

### 必学教程

- [软件测试理论基础](基础理论/软件测试理论基础教程.md)
- [ISTQB 软件测试术语速查](基础理论/ISTQB软件测试术语速查.md)
- [测试金字塔与分层策略](基础理论/测试金字塔与自动化分层策略.md)
- [探索式测试](基础理论/探索式测试教程-软件测试版.md)
- [敏捷测试](基础理论/敏捷测试教程-软件测试版.md)

### 通关任务

围绕"手机号密码登录"完成：

1. 写 15 条测试点。
2. 写 8 条测试用例。
3. 写 2 条缺陷报告示例。
4. 说明冒烟测试和回归测试区别。
5. 说明严重程度和优先级区别。

### 验收标准

| 项目 | 分值 |
|------|------|
| 测试点覆盖正常、异常、边界、权限、安全 | 30 |
| 用例包含前置条件、步骤、预期结果 | 25 |
| 缺陷报告可复现、有证据、有影响说明 | 25 |
| 能准确解释基础术语 | 20 |

通关标准：80 分以上。

### 常见扣分点

- 用例只有一句"测试登录是否正常"。
- 预期结果写"正常""正确"。
- 缺陷没有环境、步骤和实际结果。
- 把严重程度和优先级混为一谈。

### 详细通关检查

→ [第1阶段-测试入门通关](学习中心/第1阶段-测试入门通关.md)

## 三、第 2 阶段：工具实战

**建议学时：3-4 周**

### 学习目标

- 能用 SQL 校验业务数据。
- 能用 Linux 查日志、端口、进程。
- 能用 Git 完成基础协作。
- 能用 Docker 启动简单测试环境。
- 能用 Postman 调试接口。
- 能用 Fiddler 抓包分析。

### 必学教程

- [数据库 SQL](工具操作/数据库SQL教程-软件测试版.md)
- [Linux 实用](工具操作/Linux实用教程-软件测试版.md)
- [Git 版本控制](工具操作/Git版本控制教程-软件测试版.md)
- [Docker 容器](工具操作/Docker容器教程-软件测试版.md)
- [Postman 接口](工具操作/Postman接口测试教程-软件测试版.md)
- [Fiddler 抓包](工具操作/Fiddler抓包教程-软件测试版.md)
- [正则表达式](工具操作/正则表达式教程-软件测试版.md)
- [网络知识](工具操作/网络知识教程-软件测试版.md)

### 通关任务

1. 写 5 条订单查询 SQL。
2. 用 Linux 命令定位一个端口占用问题。
3. 用 Git 新建分支、提交一次修改、合并回主分支。
4. 用 Docker 启动 MySQL 或 Redis。
5. 用 Postman 调试登录接口并获取 Token。
6. 用 Fiddler 抓取登录请求分析参数。
7. 写一份"接口 500 初步排查记录"。

### 验收标准

| 项目 | 分值 |
|------|------|
| SQL 能正确关联表、过滤条件、排序和限制数量 | 25 |
| Linux 排查步骤清楚，有命令和结论 | 20 |
| Git 操作流程完整 | 15 |
| Docker 服务能启动并验证可用 | 10 |
| Postman 能调试接口并提取 Token | 15 |
| 排查记录有证据和下一步建议 | 15 |

### 常见扣分点

- SQL 不会用 JOIN 关联多表。
- Linux 不会用 grep 搜索日志。
- Git 遇到冲突直接覆盖。
- Docker 不理解镜像和容器的区别。

### 详细通关检查

→ [第2阶段-工具实战通关](学习中心/第2阶段-工具实战通关.md)

## 四、第 3 阶段：专项测试

**建议学时：2-3 周**

### 学习目标

- 理解 HTTP 请求、响应、Header、Cookie、Token。
- 能用 Postman 调试接口。
- 能设计接口测试用例。
- 能检查接口返回和数据库结果。
- 能做基础性能测试。
- 能识别常见安全风险。

### 必学教程

- [接口测试方法论](专项测试/接口测试完整教程-软件测试版.md)
- [JMeter 性能测试](专项测试/JMeter性能测试教程-软件测试版.md)
- [Web 安全测试](专项测试/Web安全测试教程-软件测试版.md)
- [Redis 与 MongoDB](工具操作/Redis与MongoDB教程-软件测试版.md)
- [接口抓包联调实战](工具操作/接口抓包联调实战教程-软件测试版.md)

### 通关任务

围绕"登录 -> 商品详情 -> 创建订单"完成：

1. 建一个 Postman Collection。
2. 配置测试环境变量。
3. 登录后自动提取 token。
4. 写 5 个接口断言。
5. 设计 10 条接口测试用例。
6. 写 3 条数据库校验 SQL。
7. 对登录接口做 10 并发性能测试。
8. 检查接口是否存在安全漏洞。

### 验收标准

| 项目 | 分值 |
|------|------|
| Collection 命名清楚，接口按模块组织 | 10 |
| 环境变量使用正确，不硬编码环境地址 | 10 |
| token 能自动提取并用于后续接口 | 15 |
| 断言覆盖状态码、业务码、字段和安全点 | 20 |
| 用例覆盖正常、异常、鉴权、数据一致性 | 20 |
| 性能测试有指标和结论 | 15 |
| 安全测试在授权环境执行并保留证据 | 10 |

### 常见扣分点

- 只断言 HTTP 200。
- token 写死。
- 不测未登录和越权。
- 不检查数据库。
- 性能测试没有结论。

### 详细通关检查

→ [第3阶段-专项测试通关](学习中心/第3阶段-专项测试通关.md)

## 五、第 4 阶段：自动化测试

**建议学时：4-6 周**

### 学习目标

- 能判断哪些用例适合自动化。
- 能写基础 Pytest 用例。
- 能做接口自动化数据驱动。
- 能写稳定的 Web UI 冒烟脚本。

### 必学教程

- [Python 基础](基础理论/Python基础教程-软件测试版.md)
- [前端基础](基础理论/前端基础教程-软件测试版.md)
- [Python 接口自动化](自动化测试/Python+Requests+Allure接口自动化教程-软件测试版.md)
- [Selenium Web 自动化](自动化测试/Selenium-Web自动化教程-软件测试版.md)
- [Playwright Web 自动化](自动化测试/Playwright自动化测试教程-软件测试版.md)
- [Appium App 自动化](自动化测试/Appium-App自动化教程-软件测试版.md)

### 通关任务

1. 画出一个项目的自动化分层表。
2. 写 5 条接口自动化用例。
3. 使用数据驱动跑登录成功和失败场景。
4. 生成一次 Allure 报告。
5. 写 3 条 Web UI 冒烟用例。
6. UI 用例失败时能保存截图或 Trace。

### 验收标准

| 项目 | 分值 |
|------|------|
| 能说明为什么某些场景不适合 UI 自动化 | 15 |
| 接口用例可独立运行，断言清楚 | 25 |
| 数据驱动结构清晰 | 15 |
| 报告能展示用例名称、步骤和失败原因 | 15 |
| Web 用例不用固定 sleep 作为主要等待方式 | 20 |
| 使用 Page Object 模式组织代码 | 10 |

### 常见扣分点

- 不理解测试金字塔，盲目堆 UI 自动化。
- 接口用例没有断言。
- Web 用例大量使用 sleep。
- 不会使用 Page Object 模式。

### 详细通关检查

→ [第4阶段-自动化测试通关](学习中心/第4阶段-自动化测试通关.md)

## 六、第 5 阶段：项目与面试

**建议学时：3-4 周**

### 学习目标

- 能完成一个小型测试项目闭环。
- 能输出测试计划、用例、缺陷和报告。
- 能把学习内容讲成项目经验。
- 能回答基础、接口、自动化、性能和安全问题。

### 必学教程

- [项目实战总览](项目实战/index.md)
- [电商系统测试实战](项目实战/电商系统测试实战.md)
- [接口自动化项目实战](项目实战/接口自动化项目实战.md)
- [Web 自动化项目实战](项目实战/Web自动化项目实战.md)
- [性能测试项目实战](项目实战/性能测试项目实战.md)
- [CI/CD 自动化回归实战](项目实战/CICD自动化回归实战.md)
- [面试专题](面试专题/index.md)

### 通关任务

围绕一个电商主流程输出：

1. 测试计划。
2. 30 条测试用例。
3. 5 条接口自动化用例。
4. 3 条缺陷示例。
5. 一份测试报告。
6. 一条 Jenkins 流水线。
7. 准备一段 2 分钟项目介绍。
8. 准备 5 个项目中的测试亮点。

### 验收标准

| 项目 | 分值 |
|------|------|
| 测试计划范围清楚，有准入准出和风险 | 15 |
| 用例覆盖主流程、异常、权限、数据一致性 | 20 |
| 自动化能在本地或流水线运行 | 15 |
| 缺陷报告清晰可复现 | 10 |
| 测试报告能给出上线建议 | 15 |
| 项目介绍有背景、职责、范围、结果 | 15 |
| 能讲清测试设计思路 | 10 |

### 常见扣分点

- 测试计划没有范围和风险。
- 用例只测正常路径。
- 自动化不能在 CI 运行。
- 项目介绍背八股答案。

## 八、最终通关标准

当你能做到下面这些，说明已经具备初级到中级测试工程师的基础能力：

- [ ] 能独立阅读需求并拆测试点。
- [ ] 能写清晰测试用例和缺陷报告。
- [ ] 能用 SQL、Linux、日志辅助定位问题。
- [ ] 能用 Postman 完成接口调试和断言。
- [ ] 能写基础接口自动化和 Web 冒烟自动化。
- [ ] 能理解测试金字塔，不盲目堆 UI 自动化。
- [ ] 能完成基础性能、安全、探索式测试。
- [ ] 能输出测试计划、测试报告和上线建议。
- [ ] 能把项目经历讲清楚，而不是只背八股答案。

通关的标志不是"看完所有教程"，而是你能拿一个真实功能，从需求分析一路做到测试结论。
