# 上线检查清单

上线检查清单用于发布前最后确认。它不能替代测试用例，但可以降低“忘记关键步骤”的风险。

## 功能确认

- [ ] 核心业务流程已测试通过。
- [ ] P0/P1 缺陷已全部关闭。
- [ ] P2 缺陷已评估影响并确认是否允许遗留。
- [ ] 回归测试已完成。
- [ ] 兼容性测试已按范围完成。
- [ ] 产品已确认关键页面和文案。

## 接口与数据

- [ ] 关键接口返回正常。
- [ ] 数据库字段变更已确认。
- [ ] 初始化数据或配置数据已准备。
- [ ] 缓存更新策略已确认。
- [ ] 定时任务影响已确认。
- [ ] 第三方接口或支付回调已验证。

## 配置与环境

- [ ] 发布版本号已确认。
- [ ] 配置文件已区分测试环境和生产环境。
- [ ] 域名、证书、端口、反向代理配置已确认。
- [ ] 数据库连接、Redis 连接、消息队列连接已确认。
- [ ] 日志路径和日志级别已确认。

## 安全与权限

- [ ] 管理员、普通用户、游客权限已验证。
- [ ] 未登录访问受限接口会被拦截。
- [ ] 敏感信息不会在页面、接口、日志中明文暴露。
- [ ] 文件上传类型和大小限制已验证。
- [ ] 关键操作有必要的权限校验或二次确认。

## 性能与稳定性

- [ ] 核心接口响应时间在可接受范围内。
- [ ] 高访问页面没有明显慢查询。
- [ ] 错误日志没有持续新增。
- [ ] 监控告警已配置或确认。
- [ ] 高峰访问风险已评估。

## 回滚方案

- [ ] 已确认回滚负责人。
- [ ] 已确认回滚命令或操作步骤。
- [ ] 数据库变更是否可回滚已确认。
- [ ] 静态资源或配置是否可恢复已确认。
- [ ] 回滚后如何验证已明确。

## 上线后验证

- [ ] 首页或入口页面可访问。
- [ ] 登录、查询、下单等核心流程可用。
- [ ] 关键接口无大量报错。
- [ ] 日志无明显异常。
- [ ] 监控指标正常。
- [ ] 用户反馈渠道已有人关注。

## 新手提醒

上线前不要只问“开发说没问题了吗”。测试需要用证据说话：用例结果、缺陷状态、接口响应、数据库数据、日志、监控指标都可以作为判断依据。
