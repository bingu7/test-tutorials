# 测试用例模板

测试用例不是简单记录“点哪里”，而是把测试思路变成可执行、可复查、可回归的步骤。

## 标准字段

| 字段 | 说明 |
|------|------|
| 用例编号 | 例如 `LOGIN-001`，方便引用和追踪 |
| 模块 | 登录、注册、购物车、订单等 |
| 测试点 | 本条用例验证什么 |
| 前置条件 | 执行前必须满足的状态 |
| 测试数据 | 账号、密码、商品、订单等 |
| 操作步骤 | 按顺序写清楚怎么执行 |
| 预期结果 | 系统应该出现什么结果 |
| 优先级 | P0/P1/P2/P3 |
| 实际结果 | 执行后填写 |
| 状态 | 通过、失败、阻塞、未执行 |
| 备注 | 截图、日志、关联缺陷等 |

## 登录功能示例

| 用例编号 | 模块 | 测试点 | 前置条件 | 测试数据 | 操作步骤 | 预期结果 | 优先级 |
|----------|------|--------|----------|----------|----------|----------|--------|
| LOGIN-001 | 登录 | 正确账号密码登录 | 用户已注册且状态正常 | `user01 / Aa123456` | 1. 打开登录页；2. 输入账号密码；3. 点击登录 | 登录成功，进入首页，显示用户昵称 | P0 |
| LOGIN-002 | 登录 | 密码错误 | 用户已注册 | `user01 / wrongpwd` | 1. 打开登录页；2. 输入账号和错误密码；3. 点击登录 | 登录失败，提示“账号或密码错误”，不进入首页 | P0 |
| LOGIN-003 | 登录 | 密码为空 | 登录页正常打开 | 账号：`user01`，密码为空 | 1. 输入账号；2. 密码不填；3. 点击登录 | 密码输入框提示必填，不发送登录请求或返回参数错误 | P1 |
| LOGIN-004 | 登录 | 连续输错密码 | 用户状态正常 | 连续输入 5 次错误密码 | 1. 连续提交错误密码；2. 第 5 次后再次登录 | 根据需求锁定账号或出现验证码校验 | P1 |
| LOGIN-005 | 登录 | 登录后刷新页面 | 已成功登录 | 正常账号 | 1. 登录成功；2. 刷新首页 | 仍保持登录状态，不跳回登录页 | P1 |

## 预期结果怎么写

好的预期结果应该具体、可判断。

| 不推荐 | 推荐 |
|--------|------|
| 登录失败 | 页面提示“账号或密码错误”，用户仍停留在登录页 |
| 添加成功 | 商品加入购物车，购物车数量 +1，数据库购物车表新增记录 |
| 系统正常 | 页面不报错，请求返回 200，列表展示 10 条数据 |

## 检查清单

- [ ] 是否覆盖正常流程。
- [ ] 是否覆盖异常输入。
- [ ] 是否覆盖边界值。
- [ ] 是否覆盖权限和登录状态。
- [ ] 是否覆盖重复提交。
- [ ] 是否有明确预期结果。
- [ ] 是否能让别人照着执行。
