# 缺陷报告模板

好的缺陷报告能让开发快速复现、快速定位、快速修复。新手提交缺陷时最常见的问题是：标题太模糊、步骤不完整、实际结果和期望结果混在一起。

## 标准字段

| 字段 | 说明 |
|------|------|
| 缺陷标题 | 简短说明问题和触发条件 |
| 所属模块 | 登录、订单、支付、后台管理等 |
| 发现版本 | 出问题的版本号或构建号 |
| 测试环境 | 测试地址、浏览器、设备、系统 |
| 前置条件 | 复现前需要准备的数据或状态 |
| 复现步骤 | 按 1、2、3 写清楚 |
| 实际结果 | 实际发生了什么 |
| 期望结果 | 按需求应该发生什么 |
| 严重程度 | Blocker/Critical/Major/Minor |
| 优先级 | P0/P1/P2/P3 |
| 附件 | 截图、录屏、日志、接口响应 |
| 关联信息 | 用例编号、需求编号、接口地址 |

## 标题写法

| 不推荐 | 推荐 |
|--------|------|
| 登录有问题 | 登录页输入错误密码后提示文案为空 |
| 下单失败 | 购物车包含下架商品时提交订单返回 500 |
| 页面异常 | iPhone 13 Safari 下商品详情页规格弹窗遮挡确认按钮 |

## 示例

| 字段 | 内容 |
|------|------|
| 缺陷标题 | 购物车包含下架商品时提交订单返回 500 |
| 所属模块 | 购物车 / 订单 |
| 发现版本 | `test-2026.06.10-01` |
| 测试环境 | Chrome 125，测试环境 `https://test-shop.example.com` |
| 前置条件 | 购物车中存在一个已下架商品 |
| 复现步骤 | 1. 登录普通用户；2. 将商品 A 加入购物车；3. 后台将商品 A 下架；4. 回到购物车点击结算 |
| 实际结果 | 页面提示“系统异常”，接口 `/api/order/create` 返回 500 |
| 期望结果 | 页面提示“商品已下架，请重新选择商品”，订单不创建 |
| 严重程度 | Major |
| 优先级 | P1 |
| 附件 | 截图、接口响应、后端日志时间点 |

## 严重程度参考

| 级别 | 说明 |
|------|------|
| Blocker | 阻塞测试或系统无法使用 |
| Critical | 核心流程失败、数据错误、资金风险、安全风险 |
| Major | 主要功能异常，但有绕过方式 |
| Minor | 文案、样式、低频兼容性问题 |

## 提交前检查

- [ ] 开发是否能按步骤复现。
- [ ] 实际结果和期望结果是否分开写。
- [ ] 是否说明测试环境和版本。
- [ ] 是否附上截图、接口响应或日志。
- [ ] 是否判断了影响范围。
- [ ] 是否关联了用例或需求。
