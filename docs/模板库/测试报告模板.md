# 测试报告模板

测试报告的作用是帮助项目成员判断：这次测试做了什么、结果如何、还有哪些风险、是否建议上线。

## 报告结构

| 模块 | 内容 |
|------|------|
| 项目概述 | 本次测试对象、版本、时间、负责人 |
| 测试范围 | 已测试功能和未测试功能 |
| 测试环境 | 环境地址、浏览器、设备、数据库、构建版本 |
| 测试执行情况 | 用例总数、通过、失败、阻塞、未执行 |
| 缺陷统计 | 按严重程度、状态、模块统计 |
| 主要问题 | 影响较大的缺陷和处理结果 |
| 遗留风险 | 未修复问题、未覆盖范围、外部依赖 |
| 测试结论 | 是否通过、是否建议上线、上线条件 |

## 测试结论写法

| 结论 | 示例 |
|------|------|
| 通过 | 核心流程已验证通过，P0/P1 缺陷已关闭，建议按计划上线 |
| 有条件通过 | 核心流程通过，存在 2 个低风险遗留问题，需产品确认后上线 |
| 不通过 | 支付回调存在 P1 缺陷，可能导致订单状态错误，不建议上线 |

## 示例结论

```text
本次测试覆盖优惠券领取、使用、过期、退款返还等核心流程，共执行 86 条用例，通过 82 条，失败 4 条。
发现缺陷 9 个，其中 P1 缺陷 2 个、P2 缺陷 5 个、P3 缺陷 2 个。
截至报告输出时，P1/P2 缺陷已全部修复并回归通过，遗留 2 个 P3 文案问题，不影响主流程。
测试结论：有条件通过，建议产品确认遗留文案问题后上线。
```

## 报告检查清单

- [ ] 数据是否真实，不能凭感觉写。
- [ ] 是否说明未测试范围。
- [ ] 是否把高风险问题单独列出。
- [ ] 是否给出明确结论。
- [ ] 是否说明遗留问题由谁确认。
