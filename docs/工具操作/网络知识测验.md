## 第 1 题：HTTP 与 HTTPS 区别

HTTPS 相比 HTTP 的主要优势是什么？

- A. 传输速度更快
- B. 通过 SSL/TLS 加密传输数据，保证数据安全性
- C. 不需要服务器证书
- D. 使用不同的端口号且不兼容 HTTP

??? success "查看答案"
    **答案：B**
    HTTPS 在 HTTP 的基础上增加了 SSL/TLS 加密层，保证数据传输的机密性和完整性。HTTPS 默认使用 443 端口（HTTP 默认 80），需要服务器配置 SSL 证书，但与 HTTP 完全兼容。

## 第 2 题：HTTP 请求方法

HTTP 请求中，GET 和 POST 方法的核心区别是什么？

- A. GET 比 POST 更安全
- B. GET 请求参数在 URL 中，POST 请求参数在请求体中；GET 用于获取资源，POST 用于提交数据
- C. GET 不能传递参数
- D. POST 不支持文件上传

??? success "查看答案"
    **答案：B**
    GET 请求的参数附在 URL 中（有长度限制），POST 请求的参数放在请求体中（无长度限制）。语义上 GET 用于获取资源，POST 用于提交/创建资源。GET 请求可被浏览器缓存，POST 默认不会。

## 第 3 题：TCP 三次握手

TCP 建立连接时的三次握手过程，正确的顺序是？

- A. SYN → SYN+ACK → ACK
- B. ACK → SYN → SYN+ACK
- C. SYN+ACK → SYN → ACK
- D. SYN → ACK → SYN+ACK

??? success "查看答案"
    **答案：A**
    TCP 三次握手：①客户端发送 SYN（同步序列号）→ ②服务端回复 SYN+ACK（确认并同步）→ ③客户端发送 ACK（确认）。三次握手确保双方都具备发送和接收能力，防止历史失效连接请求造成资源浪费。

## 第 4 题：TCP 四次挥手

TCP 断开连接时需要四次挥手的原因是什么？

- A. TCP 协议规定必须四次
- B. 因为 TCP 是全双工通信，每个方向的关闭需要单独确认
- C. 为了加快断开速度
- D. 四次挥手比三次挥手更安全

??? success "查看答案"
    **答案：B**
    TCP 是全双工协议，数据可以双向同时传输。关闭连接时，每个方向需要独立关闭：一方发送 FIN 表示不再发送数据，另一方回复 ACK 确认，然后另一方也发送 FIN，最后 ACK 确认。因此最少需要四次交互。

## 第 5 题：HTTP 状态码分类

HTTP 状态码 `200 OK` 属于哪个类别？

- A. 1xx - 信息性状态码
- B. 2xx - 成功状态码
- C. 3xx - 重定向状态码
- D. 4xx - 客户端错误状态码

??? success "查看答案"
    **答案：B**
    HTTP 状态码分为 5 类：1xx（信息）、2xx（成功）、3xx（重定向）、4xx（客户端错误）、5xx（服务器错误）。200 OK 表示请求成功，是最常见的成功状态码。

## 第 6 题：常见状态码含义

HTTP 状态码 `403 Forbidden` 的含义是？

- A. 资源不存在
- B. 服务器内部错误
- C. 服务器理解请求但拒绝执行，通常因为权限不足
- D. 请求参数错误

??? success "查看答案"
    **答案：C**
    403 Forbidden 表示服务器理解请求但拒绝授权。与 401 Unauthorized 不同，403 表示即使提供认证信息也无法访问（如 IP 黑名单、权限不足）。404 表示资源不存在，500 表示服务器内部错误。

## 第 7 题：301 与 302 重定向

HTTP 状态码 301 和 302 的区别是什么？

- A. 301 是临时重定向，302 是永久重定向
- B. 301 是永久重定向，302 是临时重定向
- C. 301 和 302 完全相同
- D. 301 用于 GET 请求，302 用于 POST 请求

??? success "查看答案"
    **答案：B**
    301 Moved Permanently 表示资源永久迁移到新地址，搜索引擎会更新索引。302 Found（原 302 Moved Temporarily）表示临时重定向，搜索引擎保留原 URL。浏览器对 301 会缓存重定向结果，302 则不会。

## 第 8 题：Cookie 的作用

Cookie 在 HTTP 通信中的主要作用是什么？

- A. 加密传输数据
- B. 在客户端存储少量数据，用于维持会话状态和记录用户信息
- C. 提高页面加载速度
- D. 压缩请求数据

??? success "查看答案"
    **答案：B**
    HTTP 是无状态协议，Cookie 是服务端通过 `Set-Cookie` 响应头写入客户端的一小段数据，客户端后续请求会自动携带。Cookie 常用于会话管理（如登录状态）、用户偏好和跟踪分析。

## 第 9 题：Session 与 Token 的区别

以下关于 Session 和 Token 认证方式的描述，哪个是正确的？

- A. Session 状态存储在客户端，Token 存储在服务端
- B. Session 状态存储在服务端，Token（如 JWT）是无状态的，服务端不存储会话信息
- C. Session 和 Token 完全相同
- D. Token 比 Session 安全性更低

??? success "查看答案"
    **答案：B**
    Session 模式下服务端存储会话状态，客户端通过 Cookie 中的 Session ID 标识身份。Token（如 JWT）是无状态的，用户信息编码在 Token 本身，服务端只需验证签名，适合分布式系统和跨服务认证。

## 第 10 题：Cookie 与 Session 的存储位置

Cookie 和 Session 的数据分别存储在哪里？

- A. Cookie 存储在服务端，Session 存储在客户端
- B. Cookie 存储在客户端浏览器，Session 数据存储在服务端
- C. 两者都存储在客户端
- D. 两者都存储在服务端

??? success "查看答案"
    **答案：B**
    Cookie 数据存储在客户端浏览器中，每次请求时自动携带。Session 数据存储在服务端内存/数据库中，客户端只保存 Session ID（通常通过 Cookie 传递）。这样敏感数据不会暴露给客户端。

## 第 11 题：DNS 解析过程

当浏览器输入 `www.example.com` 后，DNS 解析的第一步是什么？

- A. 向根域名服务器查询
- B. 查询浏览器本地 DNS 缓存
- C. 向本地 DNS 服务器（运营商）查询
- D. 直接访问目标服务器

??? success "查看答案"
    **答案：B**
    DNS 解析顺序：①浏览器缓存 → ②操作系统缓存（hosts 文件） → ③本地 DNS 服务器（运营商/配置的 DNS）→ ④根域名服务器 → ⑤顶级域名服务器 → ⑥权威域名服务器。浏览器首先检查自身缓存是否有该域名的解析记录。

## 第 12 题：DNS 记录类型

DNS 中 `A 记录` 和 `CNAME 记录` 的区别是什么？

- A. A 记录用于邮件服务，CNAME 记录用于网站
- B. A 记录将域名指向 IP 地址，CNAME 记录将域名指向另一个域名
- C. A 记录和 CNAME 记录完全相同
- D. A 记录用于 HTTPS，CNAME 记录用于 HTTP

??? success "查看答案"
    **答案：B**
    A 记录（Address Record）将域名直接映射到 IPv4 地址。CNAME（Canonical Name）记录将域名别名指向另一个域名（如 `www.example.com` → `example.com`），最终再通过目标域名的 A 记录解析到 IP。

## 第 13 题：代理服务器

在接口测试中使用正向代理的主要目的是什么？

- A. 保护后端服务器的安全
- B. 隐藏客户端真实 IP，或通过代理访问受限资源
- C. 加密数据库连接
- D. 提高 DNS 解析速度

??? success "查看答案"
    **答案：B**
    正向代理位于客户端和目标服务器之间，代表客户端发送请求。用途包括：隐藏客户端真实 IP、绕过网络限制、缓存加速等。反向代理则位于服务端前面，保护后端服务器（如 Nginx 反向代理）。

## 第 14 题：抓包工具

使用 Charles 或 Fiddler 等抓包工具进行 HTTPS 抓包时，需要做的关键配置是什么？

- A. 关闭 HTTPS 协议
- B. 安装并信任代理工具的根证书（CA 证书），以便解密 HTTPS 流量
- C. 将目标服务器的证书导入到客户端
- D. 不需要任何额外配置

??? success "查看答案"
    **答案：B**
    HTTPS 抓包的原理是中间人代理（MITM）：代理工具用自己的 CA 证书签发伪造的服务器证书，客户端需要信任该 CA 证书才能解密 HTTPS 流量。不安装证书会导致 SSL 握手失败或抓到的全是加密数据。

## 第 15 题：HTTP Keep-Alive

HTTP 的 `Connection: keep-alive` 头部的作用是什么？

- A. 保持加密状态
- B. 复用 TCP 连接，减少频繁建立和断开连接的开销
- C. 增加传输数据的大小
- D. 设置请求超时时间

??? success "查看答案"
    **答案：B**
    HTTP/1.0 默认每个请求建立一个新的 TCP 连接。`Connection: keep-alive` 允许在同一个 TCP 连接上发送多个 HTTP 请求，避免了频繁 TCP 三次握手和四次挥手的开销，显著提高传输效率。HTTP/1.1 默认启用 keep-alive。
