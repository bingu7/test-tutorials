## 选择题

<div class="quiz-container" data-quiz-id="network-basics">

<div class="quiz-item" data-correct="1">
<div class="quiz-question">HTTPS 相比 HTTP 的主要优势是什么？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q1" value="0"> 传输速度更快</label>
<label class="quiz-option"><input type="radio" name="q1" value="1"> 通过 SSL/TLS 加密传输数据，保证数据安全性</label>
<label class="quiz-option"><input type="radio" name="q1" value="2"> 不需要服务器证书</label>
<label class="quiz-option"><input type="radio" name="q1" value="3"> 使用不同的端口号且不兼容 HTTP</label>
</div>
<div class="quiz-explanation">💡 HTTPS 在 HTTP 的基础上增加了 SSL/TLS 加密层，保证数据传输的机密性和完整性。HTTPS 默认使用 443 端口，需要服务器配置 SSL 证书</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">HTTP 请求中，GET 和 POST 方法的核心区别是什么？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q2" value="0"> GET 比 POST 更安全</label>
<label class="quiz-option"><input type="radio" name="q2" value="1"> GET 请求参数在 URL 中，POST 请求参数在请求体中；GET 用于获取资源，POST 用于提交数据</label>
<label class="quiz-option"><input type="radio" name="q2" value="2"> GET 不能传递参数</label>
<label class="quiz-option"><input type="radio" name="q2" value="3"> POST 不支持文件上传</label>
</div>
<div class="quiz-explanation">💡 GET 请求的参数附在 URL 中，POST 请求的参数放在请求体中。语义上 GET 用于获取资源，POST 用于提交/创建资源。GET 请求可被浏览器缓存，POST 默认不会</div>
</div>

<div class="quiz-item" data-correct="0">
<div class="quiz-question">TCP 建立连接时的三次握手过程，正确的顺序是？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q3" value="0"> SYN → SYN+ACK → ACK</label>
<label class="quiz-option"><input type="radio" name="q3" value="1"> ACK → SYN → SYN+ACK</label>
<label class="quiz-option"><input type="radio" name="q3" value="2"> SYN+ACK → SYN → ACK</label>
<label class="quiz-option"><input type="radio" name="q3" value="3"> SYN → ACK → SYN+ACK</label>
</div>
<div class="quiz-explanation">💡 TCP 三次握手：①客户端发送 SYN → ②服务端回复 SYN+ACK → ③客户端发送 ACK。三次握手确保双方都具备发送和接收能力，防止历史失效连接请求造成资源浪费</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">TCP 断开连接时需要四次挥手的原因是什么？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q4" value="0"> TCP 协议规定必须四次</label>
<label class="quiz-option"><input type="radio" name="q4" value="1"> 因为 TCP 是全双工通信，每个方向的关闭需要单独确认</label>
<label class="quiz-option"><input type="radio" name="q4" value="2"> 为了加快断开速度</label>
<label class="quiz-option"><input type="radio" name="q4" value="3"> 四次挥手比三次挥手更安全</label>
</div>
<div class="quiz-explanation">💡 TCP 是全双工协议，数据可以双向同时传输。关闭连接时，每个方向需要独立关闭，因此最少需要四次交互</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">HTTP 状态码 200 OK 属于哪个类别？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q5" value="0"> 1xx - 信息性状态码</label>
<label class="quiz-option"><input type="radio" name="q5" value="1"> 2xx - 成功状态码</label>
<label class="quiz-option"><input type="radio" name="q5" value="2"> 3xx - 重定向状态码</label>
<label class="quiz-option"><input type="radio" name="q5" value="3"> 4xx - 客户端错误状态码</label>
</div>
<div class="quiz-explanation">💡 HTTP 状态码分为 5 类：1xx（信息）、2xx（成功）、3xx（重定向）、4xx（客户端错误）、5xx（服务器错误）。200 OK 表示请求成功，是最常见的成功状态码</div>
</div>

<div class="quiz-item" data-correct="2">
<div class="quiz-question">HTTP 状态码 403 Forbidden 的含义是？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q6" value="0"> 资源不存在</label>
<label class="quiz-option"><input type="radio" name="q6" value="1"> 服务器内部错误</label>
<label class="quiz-option"><input type="radio" name="q6" value="2"> 服务器理解请求但拒绝执行，通常因为权限不足</label>
<label class="quiz-option"><input type="radio" name="q6" value="3"> 请求参数错误</label>
</div>
<div class="quiz-explanation">💡 403 Forbidden 表示服务器理解请求但拒绝授权。与 401 不同，403 表示即使提供认证信息也无法访问。404 表示资源不存在，500 表示服务器内部错误</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">HTTP 状态码 301 和 302 的区别是什么？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q7" value="0"> 301 是临时重定向，302 是永久重定向</label>
<label class="quiz-option"><input type="radio" name="q7" value="1"> 301 是永久重定向，302 是临时重定向</label>
<label class="quiz-option"><input type="radio" name="q7" value="2"> 301 和 302 完全相同</label>
<label class="quiz-option"><input type="radio" name="q7" value="3"> 301 用于 GET 请求，302 用于 POST 请求</label>
</div>
<div class="quiz-explanation">💡 301 表示资源永久迁移到新地址，搜索引擎会更新索引。302 表示临时重定向，搜索引擎保留原 URL。浏览器对 301 会缓存重定向结果，302 则不会</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">Cookie 在 HTTP 通信中的主要作用是什么？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q8" value="0"> 加密传输数据</label>
<label class="quiz-option"><input type="radio" name="q8" value="1"> 在客户端存储少量数据，用于维持会话状态和记录用户信息</label>
<label class="quiz-option"><input type="radio" name="q8" value="2"> 提高页面加载速度</label>
<label class="quiz-option"><input type="radio" name="q8" value="3"> 压缩请求数据</label>
</div>
<div class="quiz-explanation">💡 HTTP 是无状态协议，Cookie 是服务端通过 Set-Cookie 响应头写入客户端的一小段数据，客户端后续请求会自动携带，常用于会话管理和用户偏好</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">以下关于 Session 和 Token 认证方式的描述，哪个是正确的？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q9" value="0"> Session 状态存储在客户端，Token 存储在服务端</label>
<label class="quiz-option"><input type="radio" name="q9" value="1"> Session 状态存储在服务端，Token（如 JWT）是无状态的，服务端不存储会话信息</label>
<label class="quiz-option"><input type="radio" name="q9" value="2"> Session 和 Token 完全相同</label>
<label class="quiz-option"><input type="radio" name="q9" value="3"> Token 比 Session 安全性更低</label>
</div>
<div class="quiz-explanation">💡 Session 模式下服务端存储会话状态，客户端通过 Cookie 中的 Session ID 标识身份。Token（如 JWT）是无状态的，用户信息编码在 Token 本身，适合分布式系统和跨服务认证</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">Cookie 和 Session 的数据分别存储在哪里？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q10" value="0"> Cookie 存储在服务端，Session 存储在客户端</label>
<label class="quiz-option"><input type="radio" name="q10" value="1"> Cookie 存储在客户端浏览器，Session 数据存储在服务端</label>
<label class="quiz-option"><input type="radio" name="q10" value="2"> 两者都存储在客户端</label>
<label class="quiz-option"><input type="radio" name="q10" value="3"> 两者都存储在服务端</label>
</div>
<div class="quiz-explanation">💡 Cookie 数据存储在客户端浏览器中，每次请求时自动携带。Session 数据存储在服务端，客户端只保存 Session ID，这样敏感数据不会暴露给客户端</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">当浏览器输入 www.example.com 后，DNS 解析的第一步是什么？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q11" value="0"> 向根域名服务器查询</label>
<label class="quiz-option"><input type="radio" name="q11" value="1"> 查询浏览器本地 DNS 缓存</label>
<label class="quiz-option"><input type="radio" name="q11" value="2"> 向本地 DNS 服务器（运营商）查询</label>
<label class="quiz-option"><input type="radio" name="q11" value="3"> 直接访问目标服务器</label>
</div>
<div class="quiz-explanation">💡 DNS 解析顺序：①浏览器缓存 → ②操作系统缓存 → ③本地 DNS 服务器 → ④根域名服务器 → ⑤顶级域名服务器 → ⑥权威域名服务器。浏览器首先检查自身缓存</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">DNS 中 A 记录和 CNAME 记录的区别是什么？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q12" value="0"> A 记录用于邮件服务，CNAME 记录用于网站</label>
<label class="quiz-option"><input type="radio" name="q12" value="1"> A 记录将域名指向 IP 地址，CNAME 记录将域名指向另一个域名</label>
<label class="quiz-option"><input type="radio" name="q12" value="2"> A 记录和 CNAME 记录完全相同</label>
<label class="quiz-option"><input type="radio" name="q12" value="3"> A 记录用于 HTTPS，CNAME 记录用于 HTTP</label>
</div>
<div class="quiz-explanation">💡 A 记录将域名直接映射到 IPv4 地址。CNAME 记录将域名别名指向另一个域名，最终再通过目标域名的 A 记录解析到 IP</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">在接口测试中使用正向代理的主要目的是什么？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q13" value="0"> 保护后端服务器的安全</label>
<label class="quiz-option"><input type="radio" name="q13" value="1"> 隐藏客户端真实 IP，或通过代理访问受限资源</label>
<label class="quiz-option"><input type="radio" name="q13" value="2"> 加密数据库连接</label>
<label class="quiz-option"><input type="radio" name="q13" value="3"> 提高 DNS 解析速度</label>
</div>
<div class="quiz-explanation">💡 正向代理位于客户端和目标服务器之间，代表客户端发送请求。用途包括隐藏客户端真实 IP、绕过网络限制、缓存加速等。反向代理则位于服务端前面，保护后端服务器</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">使用 Charles 或 Fiddler 等抓包工具进行 HTTPS 抓包时，需要做的关键配置是什么？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q14" value="0"> 关闭 HTTPS 协议</label>
<label class="quiz-option"><input type="radio" name="q14" value="1"> 安装并信任代理工具的根证书（CA 证书），以便解密 HTTPS 流量</label>
<label class="quiz-option"><input type="radio" name="q14" value="2"> 将目标服务器的证书导入到客户端</label>
<label class="quiz-option"><input type="radio" name="q14" value="3"> 不需要任何额外配置</label>
</div>
<div class="quiz-explanation">💡 HTTPS 抓包的原理是中间人代理：代理工具用自己的 CA 证书签发伪造的服务器证书，客户端需要信任该 CA 证书才能解密 HTTPS 流量</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">HTTP 的 Connection: keep-alive 头部的作用是什么？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q15" value="0"> 保持加密状态</label>
<label class="quiz-option"><input type="radio" name="q15" value="1"> 复用 TCP 连接，减少频繁建立和断开连接的开销</label>
<label class="quiz-option"><input type="radio" name="q15" value="2"> 增加传输数据的大小</label>
<label class="quiz-option"><input type="radio" name="q15" value="3"> 设置请求超时时间</label>
</div>
<div class="quiz-explanation">💡 Connection: keep-alive 允许在同一个 TCP 连接上发送多个 HTTP 请求，避免频繁 TCP 三次握手和四次挥手的开销，显著提高传输效率。HTTP/1.1 默认启用 keep-alive</div>
</div>
