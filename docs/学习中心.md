| 产出物 | 说明 | 用途 |

| 缺陷报告 | 记录典型缺陷和定位思路 | 面试展示问题发现 |
| 项目总结 | 汇总执行结果、风险、遗留问题和上线建议 | 面试展示总结能力 |

## 新手术语速查

如果你是零基础，可能会在学习过程中遇到一些陌生术语。这里列出最常见的术语和简单解释：

### 测试基础术语

| 术语 | 简单解释 |
|------|----------|
| 测试用例 | 描述测试步骤和预期结果的文档，告诉测试人员"怎么测"和"期望什么" |
| 缺陷（Bug） | 软件中的问题或错误，比如按钮点了没反应、数据计算错误等 |
| 测试点 | 从需求中拆分出来的需要验证的点，比如"登录时密码错误应该提示" |
| 回归测试 | 修复 Bug 后，重新测试相关功能，确保修复没有引入新问题 |
| 冒烟测试 | 快速验证核心功能是否可用，类似"先试试能不能跑起来" |

### 接口测试术语

| 术语 | 简单解释 |
|------|----------|
| 接口（API） | 程序之间通信的方式，比如前端页面调用后端服务获取数据 |
| HTTP 请求 | 浏览器或程序向服务器发送消息的方式 |
| 状态码 | 服务器返回的数字代码，200 表示成功，404 表示找不到，500 表示服务器错误 |
| Token | 登录成功后服务器发给你的"通行证"，后续请求带上它证明你已登录 |
| 断言 | 检查实际结果是否符合预期的代码，比如"返回的状态码应该是 200" |
| 抓包 | 捕获网络请求的过程，用于查看接口传了什么数据 |

### 自动化测试术语

| 术语 | 简单解释 |
|------|----------|
| 自动化测试 | 用代码代替人工执行测试，适合重复执行的场景 |
| Page Object | 一种代码组织模式，把页面元素和操作封装成类，方便维护 |
| 元素定位 | 找到页面上的按钮、输入框等元素的方式，类似"通过 ID 找到登录按钮" |
| 测试报告 | 测试执行结果的汇总文档，包含通过/失败数量、耗时等信息 |

### 工具名称

| 工具 | 用途 |
|------|------|
| Postman | 接口调试工具，用于发送请求、查看响应、编写断言 |
| Fiddler | 抓包工具，用于捕获和分析网络请求 |
| JMeter | 性能测试工具，用于模拟大量用户并发访问 |
| Selenium | Web 自动化工具，用于模拟用户在浏览器上的操作 |
| Playwright | 现代 Web 自动化工具，比 Selenium 更易用 |
| Pytest | Python 测试框架，用于编写和运行测试用例 |
| Allure | 测试报告工具，生成美观的测试报告 |

更多术语请查看 [ISTQB 术语速查](基础理论/ISTQB软件测试术语速查.md)。

## 常见问题

### Q: 我是零基础，应该从哪里开始？

从第 1 阶段「测试入门」开始，按顺序学习。先看 [软件测试理论基础](基础理论/软件测试理论基础教程.md)，建立测试思维。

### Q: 学完一个阶段后怎么判断是否可以进入下一阶段？

完成该阶段的所有必学教程，并通过阶段测验（80 分以上）。可以使用 [阶段学习检查清单](阶段学习检查清单.md) 进行自查。

### Q: 我的学习进度会丢失吗？

学习进度保存在浏览器本地（localStorage），清除浏览器缓存后会丢失。建议定期截图保存进度。

### Q: 我可以直接跳到自动化测试吗？

不建议。自动化测试需要前面阶段的基础（测试理论、SQL、Linux、接口测试）。如果直接跳到自动化，很容易变成"脚本能跑，但不知道测了什么"。
