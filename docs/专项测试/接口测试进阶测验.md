<div class="quiz-item" data-correct="1">

<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q5" value="0"> PO 模式只适用于 UI 测试</label>
<label class="quiz-option"><input type="radio" name="q5" value="1"> PO 模式将接口封装为业务对象，测试脚本只调用业务方法</label>
<label class="quiz-option"><input type="radio" name="q5" value="2"> PO 模式要求每个接口必须写一个类</label>

</div>
<div class="quiz-explanation">💡 PO 模式的核心思想是封装与分离。在接口测试中，将底层接口调用封装为业务层方法，测试脚本只需调用业务方法，降低脚本与接口实现的耦合度</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">在接口测试中使用 Mock 服务的主要目的是什么？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q7" value="0"> 提高测试代码的执行速度</label>
<label class="quiz-option"><input type="radio" name="q7" value="1"> 模拟依赖服务的响应，使测试可以在依赖不可用时正常进行</label>
<label class="quiz-option"><input type="radio" name="q7" value="2"> 替代所有真实接口测试</label>
<label class="quiz-option"><input type="radio" name="q7" value="3"> 减少测试用例的数量</label>
</div>
<div class="quiz-explanation">💡 Mock 服务用于模拟第三方接口或未完成的依赖服务的返回值，使测试不依赖外部环境。这在微服务架构中尤为重要，可以隔离测试目标服务，提高测试的独立性和稳定性</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">以下哪种鉴权方式在接口测试中最为常见？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q8" value="0"> 将用户名和密码放在 URL 路径中</label>
<label class="quiz-option"><input type="radio" name="q8" value="1"> 使用 Token（如 JWT）放在请求头 Authorization 字段中</label>
<label class="quiz-option"><input type="radio" name="q8" value="2"> 在请求体中明文传递密码</label>
<label class="quiz-option"><input type="radio" name="q8" value="3"> 不需要任何鉴权</label>
</div>
<div class="quiz-explanation">💡 Token 鉴权（如 JWT）是目前最主流的接口鉴权方式。客户端登录后获取 Token，后续请求通过 Authorization 头部携带，服务端验证 Token 有效性，避免每次传输密码</div>
</div>

<div class="quiz-item" data-correct="1">
<div class="quiz-question">以下哪种测试属于接口参数篡改测试？</div>
<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q9" value="0"> 测试接口的正常返回</label>
<label class="quiz-option"><input type="radio" name="q9" value="1"> 修改请求中的用户 ID 为其他用户 ID，验证是否能获取他人数据</label>
<label class="quiz-option"><input type="radio" name="q9" value="2"> 测试接口响应时间</label>
<label class="quiz-option"><input type="radio" name="q9" value="3"> 验证接口文档的完整性</label>
</div>
<div class="quiz-explanation">💡 参数篡改测试属于安全测试范畴，主要验证接口是否存在越权访问漏洞。通过修改请求参数检查服务端是否做了权限校验，防止未授权访问</div>
</div>

</div>

</div>

<div class="quiz-options">
<label class="quiz-option"><input type="radio" name="q14" value="0"> 接口的响应速度</label>
