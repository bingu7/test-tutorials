# 面试复盘清单

面试结束后不要只记得“感觉还行”或“没发挥好”。复盘的目的是找出薄弱点，让下一次回答更具体。

## 面试后立刻记录

- [ ] 公司和岗位名称。
- [ ] 面试时间和轮次。
- [ ] 面试官重点问了哪些方向。
- [ ] 哪些问题回答顺利。
- [ ] 哪些问题卡住了。
- [ ] 哪些项目细节没有说清楚。
- [ ] 是否有笔试、实操或作业。

## 问题分类

| 类型 | 例子 | 复盘方式 |
|------|------|----------|
| 基础概念 | 冒烟和回归区别 | 回到基础理论补概念和例子 |
| 工具操作 | Postman 环境变量怎么用 | 实际操作一遍并截图记录 |
| 项目经验 | 你负责哪些模块 | 按项目表达结构重写回答 |
| 自动化 | 框架怎么设计 | 画出目录结构和运行流程 |
| 排查能力 | 接口报 500 怎么定位 | 写出排查步骤 |
| 职业理解 | 为什么做测试 | 准备真实、清楚的动机回答 |

## 每周补强计划

| 天数 | 任务 |
|------|------|
| 第 1 天 | 整理面试问题，标记不会的 |
| 第 2 天 | 补软件测试基础和用例设计 |
| 第 3 天 | 补接口测试和 HTTP 基础 |
| 第 4 天 | 补 SQL、Linux、Git 高频操作 |
| 第 5 天 | 重写项目经验表达 |
| 第 6 天 | 模拟回答 10 个问题 |
| 第 7 天 | 复盘并更新简历项目描述 |

## 常见信号

| 面试表现 | 说明 |
|----------|------|
| 只能说工具名 | 项目细节不足 |
| 回答没有例子 | 可能只是背概念 |
| 遇到追问就卡住 | 对原理或流程理解不够 |
| 项目职责说不清 | 简历描述需要重写 |
| 不知道缺陷怎么定位 | 实战排查经验不足 |

## 最终目标

每次面试结束后，至少沉淀三类内容：

- 一个更好的问题答案。
- 一个更清楚的项目表达。
- 一个需要补练的实操任务。
