# 简历撰写与项目包装

技术都会了，简历投出去却没回音——问题通常不在能力，而在**简历没有把能力翻译成 HR 和面试官能快速识别的信号**。

这一篇解决三个问题：简历该长什么样、技能和项目怎么写、哪些写法会直接让你被筛掉。

---

## 一、先理解谁在看你的简历

简历要过两道关，两道的关注点完全不同：

```text
第一关：HR / 招聘专员（平均看 10-30 秒）
  看什么：学历、年限、岗位匹配度、期望薪资、稳定性
  筛掉你的原因：关键词不匹配、学历不符、薪资超预算、跳槽频繁

第二关：技术面试官（平均看 2-3 分钟）
  看什么：技术栈深度、项目真实性、能不能聊出细节
  筛掉你的原因：技术栈太泛像背的、项目是"参与"而非"负责"、没有量化结果
```

!!! abstract "关键结论"
    **简历要同时满足两类读者**：
    - 给 HR 看的部分（基本信息、技能关键词、学历、年限）要**醒目、标准、可检索**
    - 给技术官看的部分（项目经验）要**具体、有细节、有数字**，能撑住追问

    只堆技术栈 → HR 觉得匹配但技术官觉得空洞；只写项目故事 → 技术官认可但 HR 检索不到关键词。两个都要。

## 二、测试简历的标准结构

### 2.1 推荐顺序

| 顺序 | 模块 | 篇幅 | 说明 |
|------|------|------|------|
| 1 | 基本信息 | 2-3 行 | 姓名、电话、邮箱、求职意向、期望薪资 |
| 2 | 教育经历 | 1-2 行 | 应届生必放前面；社招可放最后 |
| 3 | 专业技能 | 8-12 行 | **核心模块**，按重要性排序 |
| 4 | 工作/实习经历 | 4-8 行 | 有经验者放最前，务必带量化 |
| 5 | 项目经验 | 6-12 行 | **最能撑住面试追问的部分** |
| 6 | 证书/其他 | 1-2 行 | 有则写，无则删 |

**应届生**：教育 → 技能 → 实习 → 项目
**转岗者**：技能 → 项目 → 原工作可转化的能力 → 教育
**社招**：技能 → 工作经历（含项目）→ 项目经验 → 教育

### 2.2 篇幅控制

!!! warning "一页还是两页"
    - **3 年以下经验**：1 页。超过 1 页说明你不会取舍。
    - **3-8 年**：1-2 页。
    - **8 年以上**：2 页，可加管理/架构内容。

    但要分清"页数"和"密度"：一页塞满 10 号字不如两页排得清楚。**排版的可读性比省纸重要**。

### 2.3 基本信息里的三个易错点

| 项目 | 错误写法 | 正确写法 |
|------|----------|----------|
| 期望薪资 | "面议" | 写区间（如 `10-13K`）或直接删掉，面试再谈。写"面议"会被认为没想清楚，也容易被压价 |
| 求职意向 | 不写 | 明确写"软件测试工程师"，方便 HR 归类 |
| 照片 | 放生活照 | 不放或放职业照；技术岗照片不是加分项 |

## 三、专业技能怎么写

这是最容易写废的部分。绝大多数简历在这里写成了**技术栈清单**：

```text
❌ 常见写法（等于没说）
熟悉测试理论、测试流程、测试用例设计
熟悉 Postman、JMeter、Fiddler 等工具
熟悉 MySQL、Linux、Git
了解 Python、Selenium
```

面试官看完的反应是："这些人人都会写。" 因为没有**程度**、没有**能做什么**。

### 3.1 正确写法：能力 + 能做到什么

每一条技能都用「**掌握程度 + 具体能力 + 应用结果**」三段式：

```text
✅ 推荐写法
测试设计：能独立完成需求评审与测试点拆解，熟练运用等价类、边界值、场景法、
判定表设计用例，主导过 3 个模块共 150+ 条用例的编写与维护。

接口测试：能根据接口文档设计正向、异常、鉴权、幂等、数据一致性用例；
用 Postman 管理多环境变量与断言，用 JMeter 完成 200 并发压测并输出
TPS/RT/错误率分析报告。

自动化：掌握 Python + Pytest + Requests，能封装统一请求基类、处理 Token
续期与请求重试；实现 Excel/JSON 数据驱动与多环境切换；接入 GitHub Actions
实现提交即回归。

数据库与排查：能编写多表 JOIN、子查询完成业务数据校验；会用 grep/awk/tail
组合检索日志，通过 top/netstat/df 定位 CPU、端口占用、磁盘问题。
```

### 3.2 掌握程度词的分级

!!! warning "别乱用'精通'"
    面试官看到"精通"会专门挑最难的问。真实的程度分级：

| 词 | 含义 | 使用建议 |
|----|------|----------|
| 了解 | 知道概念，没实操过 | 慎写，面试官一追问就露 |
| 熟悉 | 用过，能做常规操作 | 可以写，但要准备好被问细节 |
| 熟练 | 独立完成过，遇到问题能自己解决 | **推荐大量使用** |
| 掌握 | 有系统性理解，能讲原理 | 用在你真能讲原理的地方 |
| 精通 | 能优化、能教别人、了解底层实现 | **3 年以下不要写** |

### 3.3 技能栈排序原则

**按目标岗位 JD 的匹配度排序，不按你学的顺序排。**

```text
如果投接口测试岗：
  1. 接口测试（HTTP、断言、鉴权、幂等）
  2. 抓包与联调（Fiddler/Charles）
  3. 接口自动化（Python + Pytest + Requests）
  4. 数据库与日志排查
  5. 性能测试
  6. CI/CD

如果投自动化岗：
  1. 编程语言（Python 优先）
  2. 自动化框架（Pytest/Playwright/Selenium + PO + 数据驱动）
  3. 报告与 CI 集成（Allure + Jenkins/Actions）
  4. 接口测试
  5. 版本管理（Git）
```

!!! tip "一个实操技巧"
    针对不同岗位准备**2-3 个版本**的简历，只调整技能栈顺序和项目侧重点，主体内容复用。投接口岗就把接口相关提到第一行——HR 在前 10 秒扫到的关键词决定了你进不进第二轮。

## 四、项目经验怎么写（最重要的一节）

### 4.1 核心公式

```text
项目名 + 背景与问题 → 我的职责范围 → 具体动作（可量化）→ 结果与收益
```

很多简历写成这样：

```text
❌ 无效写法
项目：某电商系统测试
职责：负责功能测试和接口测试，编写测试用例，提交缺陷。
```

问题在于：**没有任何可追问的信息**。面试官只能问"用了什么工具"，问完就没话了，你对项目的贡献完全体现不出来。

### 4.2 改写示范

```text
✅ 有效写法
项目：电商 App 下单流程质量保障（2025.10-2026.04）

背景：大促前发现历史版本存在"库存超卖"和"优惠券重复使用"问题，
      手工回归单轮耗时约 4 小时，且容易遗漏组合场景。

职责：独立负责【首页秒杀】【购物袋】【分类】三大核心模块的测试设计与执行。

动作：
- 基于满减阶梯、会员折扣叠加、库存扣减规则设计 150+ 条用例，
  用判定表覆盖 40+ 种优惠组合；
- 用 JMeter 模拟秒杀开抢瞬时峰值（200 并发/秒），
  监控响应时间与后端资源，验证高并发下无重复下单与库存负数；
- 用 SQL 校验订单状态、库存字段与优惠金额的一致性，
  发现 3 处前端展示与数据库不一致问题。

结果：累计提交有效缺陷 30+ 个，修复率 95%；拦截库存超卖缺陷 1 个
      （资损风险）；沉淀核心模块回归用例集，后续版本回归时间
      从 4 小时压缩到 1.5 小时。
```

### 4.3 面试官会追问什么

写下每个项目之前，先自己回答下面这些问题。**答不上来的内容不要写进简历**：

| 追问 | 你要能说清 |
|------|-----------|
| 这个项目多大？ | 团队规模、测试人数、你的角色 |
| 你负责多少？ | 模块数、用例数、缺陷数、独立还是协作 |
| 最难的缺陷是什么？ | 现象、定位过程、根因、解决方式 |
| 测试范围怎么定的？ | 什么测、什么不测、为什么 |
| 有没有漏测？ | 举一个，说清原因和改进措施 |
| 自动化覆盖多少？ | 具体比例和覆盖范围，别报 100% |
| 数据怎么造？ | 固定数据 + 运行时构造的分层思路 |
| 环境怎么管？ | 多环境切换方式、配置分离 |

!!! warning "别报 100% 覆盖率"
    ```
    面试官：你们自动化覆盖率多少？
    你：100%。
    → 面试官会开始追问细节，然后你露馅。
    ```
    真实可信的回答：

    "核心接口覆盖率大约 70%，UI 层只覆盖了 5 条核心流程。覆盖率不是目标，
    重点是覆盖了最有业务价值的场景。我们定期 review 用例，把维护成本高
    但价值低的用例下掉。"

### 4.4 没有真实项目怎么办

!!! abstract "三条可行路径"
    **路径一：开源项目实战（推荐）**
    找一个可运行的开源系统（如 mall、vue-shop 类电商项目），本地跑起来，
    完整走一遍：需求分析 → 用例设计 → 接口测试 → 自动化 → 报告。
    产出的用例、脚本、报告、CI 记录就是你的项目材料。

    注意：**必须写清这是你自己发起的练习项目**，不要说成公司项目。
    面试官对"自学项目"是认可的态度，对"编造的公司项目"是零容忍。

    **路径二：把课程作业做深**
    培训班的项目普遍偏浅（就是做一遍 demo）。你可以横向加深：
    别人只写 5 条用例，你写 30 条并覆盖边界与异常；别人只调通接口，
    你还做了数据驱动和 CI 集成。

    **路径三：把实习做透**
    实习时间短不代表产出少。哪怕只参与了一个模块，也能写清楚
    "我设计了哪些用例、发现了什么缺陷、推动了什么改进"。

### 4.5 项目材料的呈现

面试时**带上可展示的实物**，比口头说更有说服力：

| 材料 | 形式 | 作用 |
|------|------|------|
| 测试用例 | Excel / 截图 | 证明设计能力 |
| 缺陷记录 | 禅道/Jira 截图 | 证明流程规范 |
| 自动化代码 | GitHub 仓库链接 | 证明编码能力（**最有价值**） |
| 测试报告 | PDF | 证明总结能力 |
| CI 运行记录 | 流水线截图 | 证明工程能力 |

!!! tip "GitHub 仓库是应届生最大的加分项"
    把自动化项目整理成一个结构清晰的仓库：
    ```
    ├── README.md          # 项目说明、技术栈、运行方式、截图
    ├── requirements.txt
    ├── config/            # 多环境配置
    ├── api/               # 接口封装
    ├── testcases/         # 用例
    ├── data/              # 数据驱动文件
    ├── utils/             # 工具（日志、断言、数据库）
    └── .github/workflows/ # CI 配置
    ```
    README 里放上 Allure 报告截图和 CI 运行截图。
    **面试官会打开看**——这是你和"只有纸面简历的人"的决定性差距。

## 五、会让你被筛掉的写法

### 5.1 造假（后果最严重）

!!! danger "简历造假的真实代价"
    **技术岗的造假极易被识破**，因为面试就是深度追问：

    | 造假内容 | 追问后如何露馅 |
    |----------|----------------|
    | 写了没用过的工具 | 问"你们禅道的缺陷流转怎么配的"→ 答不上 |
    | 夸大职责 | 问"这个框架的分层怎么设计的"→ 只会背概念 |
    | 编造项目 | 问"当时的并发量是多少、瓶颈在哪"→ 数字对不上 |
    | 虚报年限/学历 | 背调直接查出，offer 撤销 |

    技术面试官判断真假的方法很简单：**连问三层"为什么"**。
    真做过的人能答到第二三层，编的人在第二层就绕回概念了。

    比造假更严重的是**代价不可逆**：部分公司会加入行业黑名单，
    背景调查发现问题会被直接辞退且不留证据。

### 5.2 其他常见问题

| 问题 | 表现 | 修正 |
|------|------|------|
| 技术栈堆砌 | 列出 20 个工具，每个都"熟悉" | 只留和目标岗位强相关的 8-10 个 |
| 全是"参与" | 通篇"参与了 XX 项目" | 改成"负责 XX 模块，独立完成 XX" |
| 没有数字 | 看不到任何量化 | 至少 3 处数字：用例数、缺陷数、效率提升 |
| 岗位错位 | 投测试岗写大量开发内容 | 开发能力作为加分项，不占主要篇幅 |
| 格式混乱 | 字号不一、对齐错乱 | 用统一模板，检查转 PDF 后的效果 |
| 文件名随意 | `简历.pdf`、`新建文档.pdf` | 用 `姓名-岗位-年限.pdf`，如 `王彬-软件测试-应届.pdf` |
| 有错别字 | 工具名拼错、术语写错 | 逐字校对，**拼错"Pytest"是硬伤** |

### 5.3 关于"技能雷达图"和"自我评价"

!!! warning "这两个模块通常减分"
    - **技能雷达图**：无法量化，面试官无法验证，还占版面。删掉。
    - **"我学习能力强、抗压能力强、有责任心"**：所有简历都这么写，等于没写。如果一定要写自我评价，用**事实**代替形容词：

    ```
    ❌ 自我评价：学习能力强，责任心强，抗压能力强，团队协作好。

    ✅ 用事实表达：
    - 自学 Python 自动化并在 3 个月内落地接口回归，替代了原手工回归流程；
    - 实习期间独立承担 3 个模块测试，缺陷有效率 95%；
    - 参与每日站会并输出阶段性质量报告，推动 30+ 缺陷按期闭环。
    ```

## 六、简历自查清单

投出去之前逐条核对：

**结构**
- [ ] 一页（或两年内经验一页）
- [ ] 有明确的求职意向和期望薪资（或已删除薪资）
- [ ] 文件名是「姓名-岗位-年限」

**技能**
- [ ] 每条技能都写清了"能做到什么"，不是工具名罗列
- [ ] 技术栈按目标岗位匹配度排序
- [ ] 没有出现"精通"（除非真的能讲底层）
- [ ] 没有写没用过的工具

**项目**
- [ ] 每个项目都有"背景 → 职责 → 动作 → 结果"四段
- [ ] 至少 3 处量化（用例数、缺陷数、效率提升、并发量）
- [ ] 用的都是"负责/独立完成/主导"，不是"参与"
- [ ] 每个项目都能回答"最难的缺陷是什么、怎么定位的"
- [ ] 没有报"100% 覆盖率"

**其他**
- [ ] 无错别字，技术名词拼写正确
- [ ] 导出 PDF 后排版正常、无乱码
- [ ] 附上了 GitHub 或作品材料链接（如果有）

## 七、一个完整的参考骨架

```text
姓名 | 求职意向：软件测试工程师 | 电话 | 邮箱 | 期望薪资 10-13K

教育经历
XX大学 软件工程 本科 2022.09-2026.06
（应届生放前面；英语四级可写，其他视情况）

专业技能
测试设计：能独立完成需求评审与测试点拆解，熟练运用等价类、边界值、
场景法、判定表，主导过 X 个模块共 N 条用例的设计与维护。
缺陷管理：熟练使用禅道/Jira 完成缺陷提交与全流程跟踪，能通过模块分布、
收敛趋势、重开率等报表支撑上线决策。
接口测试：能设计正向、异常、鉴权、幂等、数据一致性用例；用 Postman
管理多环境变量与断言；用 JMeter 完成 N 并发压测并输出分析报告。
自动化：掌握 Python + Pytest + Requests，能封装请求基类、处理 Token
续期与重试；实现数据驱动与多环境切换；接入 CI 实现提交即回归。
数据库与排查：能编写多表 JOIN、子查询做数据校验；能用 grep/awk/tail
检索日志，通过 top/netstat/df 定位环境问题。
抓包与联调：熟练使用 Fiddler/Charles 抓取 HTTP/HTTPS 流量，分析报文、
模拟弱网、篡改参数验证前后端容错。

实习/工作经历
公司名 | 岗位 | 起止时间
【全流程质量保障】负责 XX 模块，设计 N 条用例，提交缺陷 N 个，修复率 X%。
【性能保障】用 JMeter 模拟 N 并发，监控资源，验证 XX 场景。
【自动化落地】用 Python + Pytest 实现接口自动化，接入 CI，回归时间从 X 到 Y。

项目经验
项目名 | 起止时间 | 技术栈
背景：遇到了什么问题（用数字说明痛点）
职责：我负责什么范围
动作：我具体做了什么（分点，可量化）
结果：带来了什么收益（用数字）

其他
证书 / GitHub 链接 / 作品材料
```
