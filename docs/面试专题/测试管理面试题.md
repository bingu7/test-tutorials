# 测试管理面试题

测试管理面试重点包括测试策略制定、团队管理、质量度量和流程改进。

## 测试策略和测试计划有什么区别？

```text
测试策略：
- 宏观层面：测什么、怎么测、用什么方法
- 回答：测试范围、测试类型、测试方法、风险评估
- 通常一个项目或产品一份

测试计划：
- 执行层面：谁测、什么时候测、测多久
- 回答：人员分工、时间安排、环境准备、里程碑
- 通常每个版本或迭代一份
```

## 怎么评估测试工作量？

```text
常用方法：

1. 经验估算法
   - 根据类似项目的历史数据
   - 适合团队有积累的情况

2. 用例点估算法
   - 用例数 × 平均执行时间
   - 加上用例设计、环境准备、回归的时间

3. 功能点估算法
   - 根据需求的功能点数量
   - 每个功能点对应的测试工作量

4. 三点估算法
   - 乐观时间、最可能时间、悲观时间
   - 公式：(乐观 + 4×最可能 + 悲观) / 6

建议：留 20-30% 的缓冲时间应对突发情况。
```

## 怎么管理测试团队？

```text
关键点：

1. 任务分配
   - 根据成员能力分配模块
   - 新人配导师，复杂模块给有经验的人

2. 进度跟踪
   - 每日站会同步进展和阻塞
   - 用看板或工具（Jira、禅道）跟踪状态

3. 质量把控
   - 用例评审：确保覆盖全面
   - 缺陷复盘：分析漏测原因
   - 代码审查：自动化脚本质量

4. 能力培养
   - 定期技术分享
   - 鼓励学习新工具和方法
   - 给成员成长空间
```

## 测试左移和右移是什么？

```text
测试左移（Shift Left）：
- 把测试活动提前到需求和设计阶段
- 做法：参与需求评审、接口文档评审、代码审查
- 好处：更早发现问题，修复成本更低

测试右移（Shift Right）：
- 把测试延伸到生产环境
- 做法：线上监控、灰度发布、A/B 测试、用户反馈
- 好处：发现测试环境无法覆盖的问题

两者结合 = 全流程质量保障
```

## 怎么度量测试质量？

```text
常用指标：

1. 缺陷相关
   - 缺陷密度：缺陷数 / 千行代码
   - 缺陷逃逸率：线上缺陷数 / 总缺陷数
   - 缺陷修复率：已修复 / 总缺陷数

2. 用例相关
   - 用例覆盖率：已执行 / 总用例数
   - 自动化覆盖率：自动化用例 / 可自动化用例

3. 效率相关
   - 测试执行效率：用例数 / 人天
   - 缺陷发现效率：缺陷数 / 人天

4. 质量趋势
   - 每个版本的缺陷趋势
   - 线上事故数趋势

注意：指标是手段不是目的，不要为了指标而指标。
```

## 上线前发现严重 Bug 怎么处理？

```text
处理步骤：

1. 评估影响
   - 影响范围：是核心功能还是边缘功能
   - 影响用户：是所有用户还是部分用户
   - 是否涉及资金、数据安全

2. 决策
   - 阻塞性 Bug → 延期发布
   - 非阻塞但严重 → 评估是否带病上线 + 监控
   - 低风险 → 记录后续版本修复

3. 沟通
   - 通知产品经理和项目经理
   - 说明风险和建议
   - 记录决策过程

4. 后续
   - 补充用例防止再次漏测
   - 复盘为什么测试阶段没发现
```

## 怎么推动开发写单元测试？

```text
策略：

1. 用数据说话
   - 统计线上 Bug 中有多少本可以通过单元测试发现
   - 展示单元测试对代码质量的影响

2. 降低门槛
   - 提供测试框架和示例
   - 先从核心模块开始

3. 流程保障
   - CI/CD 中加入单元测试覆盖率门禁
   - 覆盖率低于阈值阻断部署

4. 文化建设
   - 不要对立，要协作
   - 代码审查时一起看测试质量
   - 表彰写测试好的团队
```

## 测试计划工作的关键是什么？

```text
关键要素：

1. 测试目标：明确测什么、达到什么质量标准
2. 测试范围：哪些功能需要测试，哪些不测
3. 测试资源：人员分工、工具、环境
4. 测试进度：时间节点、里程碑
5. 测试方法：功能测试、接口测试、自动化测试怎么分配
6. 风险控制：需求变更、开发延期、环境不稳定等风险的应对方案

一个好的测试计划能让测试工作有条理，减少后期沟通成本。
```
