# 岗位JD对照与投递策略

学会读 JD（Job Description，岗位描述），是求职效率的分水岭。

同一个人的同一份简历，会读 JD 的人命中率能高出几倍——因为**他不是在广撒网，而是在做匹配**。

这一篇讲清：JD 里哪些是硬性门槛、哪些是"加分项"其实不重要、怎么对着 JD 改简历、怎么判断值不值得投。

---

## 一、JD 的真实结构

一份 JD 通常长这样，但**读法顺序和它写的顺序不一样**：

```text
【公司介绍】     ← 基本不看（都是套话）
【岗位职责】     ← 第 2 位看：判断你要做什么
【任职要求】     ← 第 1 位看：判断你能不能投
【加分项/优先】   ← 第 3 位看：判断你的竞争优势
```

### 1.1 读 JD 的正确顺序

!!! abstract "三步读法"
    1. **先读「任职要求」，把硬性条件圈出来**——决定你能不能过 HR 筛
    2. **再读「岗位职责」，判断工作内容你是否愿意做**——决定你干不干得下去
    3. **最后读「加分项」，判断你的差异化在哪**——决定面试怎么突出自己

## 二、任职要求里的硬性门槛

任职要求通常混合了三类信息，要拆开看：

| 类型 | 特征词 | 能不能突破 | 处理方式 |
|------|--------|-----------|----------|
| **硬性门槛** | "统招本科及以上"、"X 年以上经验"、"持有 XX 证书" | ❌ 基本不能 | 不符就跳过，别浪费投递额度 |
| **技能要求** | "熟练使用 XX"、"掌握 XX"、"了解 XX" | 🟡 部分可突破 | 符合的交，不符合的快速补 |
| **软性要求** | "良好的沟通能力"、"责任心强" | ✅ 面试体现 | 不用管，人人都写 |

### 2.1 学历门槛的实际情况

| JD 写法 | 实际含义 |
|---------|----------|
| 统招本科及以上 | **硬门槛**，学信网可查，转岗/专科基本没戏 |
| 本科及以上（未写"统招"） | 常可放宽，自考/成考有机会，可尝试 |
| 大专及以上 | 明确接受专科 |
| 学历不限 / 能力优先 | 真看能力，但这类岗位通常薪资偏低或要求极强 |

!!! tip "一个可操作的判断"
    JD 里出现"**学信网可查**"四个字，说明公司查得严，不要尝试突破。
    只写"本科及以上"，可以先投，HR 筛掉也不损失什么。

### 2.2 经验年限的灵活性

| JD 写法 | 实际情况 |
|---------|----------|
| 3-5 年 | 2 年且项目匹配度高，可以投 |
| 5 年以上 | 3-4 年且能力突出，可以投（但被筛概率大） |
| 1-3 年 | 应届生有实习经历可以投 |
| 经验不限 | 直接投 |

!!! abstract "越级投递的原则"
    **差 1 年且技能高度匹配 → 投**；**差 2 年以上 → 不投**。

    判断依据不是年限，而是"**这个岗位的活你能不能干**"。如果 JD 里列的技术栈你都熟，年限差 1 年不是问题；如果差 3 年，说明岗位要求的能力层级和你不在一个层次。

### 2.3 技能要求的分级识别

JD 里的技能词也有优先级：

```text
"精通 XX"      → 面试会深挖，你没有就别投
"熟练使用 XX"   → 必须会，且能讲细节
"掌握 XX"      → 会用即可
"了解 XX"      → 知道概念就行，可以现场学
"XX 优先"      → 加分项，不影响投递
```

!!! warning "关键判断：区分「必须」和「优先」"
    ```
    ❌ 别被这种 JD 吓退：
    "熟悉 Kubernetes、有大数据测试经验、了解 Go 语言者优先"
    → 三个都是"优先"，说明是加分项，不是门槛。

    ✅ 但要注意这种：
    "精通 JMeter，能独立完成全链路压测方案设计与瓶颈定位"
    → "精通" + 具体能力描述，面试一定深挖。
    ```

## 三、把 JD 拆成技能矩阵

拿到目标 JD，不要凭感觉判断"我符不符合"，要**逐条对照打分**。

### 3.1 对照表模板

以一份真实的接口测试岗 JD 为例：

| JD 要求 | 原文关键词 | 我的状态 | 证据 | 应对 |
|---------|-----------|----------|------|------|
| 精通接口测试工具 | Postman、JMeter、SoapUI | ✅ 会前两个 | 实习做过接口测试 | 直接写 |
| 掌握抓包工具 | Fiddler、Charles、Wireshark | 🟡 前两个会，Wireshark 只了解 | 无 | 快速补 Wireshark |
| SQL 复杂查询 | 多表查询、数据校验 | ✅ 熟练 | 用 SQL 校验过库存 | 直接写 |
| 理解 HTTP/HTTPS 协议 | RESTful API 规范 | ✅ 掌握 | 会分析请求响应 | 直接写 |
| 敏捷实践 | Scrum/Kanban | ✅ 有 | 参与过每日站会 | 直接写 |
| 自动化框架经验 | Pytest、TestNG、RestAssured | 🟡 只会 Pytest | 有接口自动化项目 | 写 Pytest，说明框架封装 |
| 性能瓶颈分析 | 压测并分析瓶颈 | 🟡 会压测，瓶颈分析浅 | 做过 JMeter 压测 | 补瓶颈定位 |

### 3.2 匹配度评分

```text
✅ 完全符合 → 2 分
🟡 部分符合 → 1 分
❌ 不符合   → 0 分

匹配度 = 得分 / 总分

≥ 70%  → 优先投递，重点准备
50-70% → 可以投，但要补 1-2 个关键短板
< 50%  → 先别投，补完再投
```

!!! abstract "一个重要认知"
    **不要追求 100% 匹配**。JD 是"理想人选"的画像，实际录用的人通常只有 60-70% 匹配。追求 100% 匹配会让你觉得什么都投不了。

    真正要警惕的是**核心技能缺失**：如果 JD 的核心要求（通常排在前两三条）你完全不会，那投了也是白投。

### 3.3 用对照表反推补课方向

对照表最大的价值不是"决定投不投"，而是**告诉你该补什么**：

```text
如果多个目标 JD 都要求某项技能，而你没有 → 这是必须补的
如果只有某一份 JD 要求 → 优先级低，可以不补
```

!!! tip "批量分析方法"
    收集 10 份目标岗位 JD，把技能要求全部列出来做**词频统计**：

    ```
    出现 8 次以上 → 必补（这是行业门槛）
    出现 4-7 次   → 建议补
    出现 1-3 次   → 按兴趣补
    ```

    这个方法能帮你避免"学了一堆某公司才要的冷门技能"。

## 四、针对性改简历

同一份简历投所有岗位，是效率最低的做法。**投递前按 JD 调整三个地方**：

### 4.1 技能栈顺序

把 JD 里提到、且你会的内容**提到前面**：

```text
投接口岗前：
  接口测试 ← 移到第一行
  抓包与联调 ← 移到第二行
  ...
  自动化测试 ← 往后放

投自动化岗前：
  自动化框架 ← 移到第一行
  编程语言 ← 移到第二行
  ...
  接口测试 ← 往后放
```

HR 在前 10 秒扫的就是前几行，这决定了你能不能进技术面。

### 4.2 项目侧重点

同一个项目，对不同岗位**突出不同的动作**：

| 投什么岗 | 突出项目的哪个部分 |
|----------|-------------------|
| 功能测试 | 用例设计方法、缺陷发现、覆盖率、业务理解 |
| 接口测试 | 接口用例设计、断言策略、鉴权、数据校验 |
| 自动化 | 框架封装、数据驱动、CI 集成、维护成本优化 |
| 性能测试 | 场景设计、并发模型、指标分析、瓶颈定位 |

!!! abstract "举例"
    你有一个"接口自动化测试平台"项目，投不同岗位时：

    **投自动化岗**：
    > 封装统一 HTTP 请求基类，解决 Token 过期导致用例批量失败的问题，
    > 实现会话管理与自动续期；统一断言与日志封装，新增用例冗余代码
    > 降低约 40%。

    **投接口测试岗**：
    > 覆盖 30+ 业务接口的入参校验与状态码断言，基于 Excel/JSON 数据驱动
    > 实现测试数据与脚本分离；内置 Mock 响应篡改模块，在接口未就绪时
    > 即可离线验证前端容错逻辑。

    **同一个项目，前者突出工程能力，后者突出测试设计能力。**

### 4.3 关键词对齐

很多公司用系统做**简历关键词初筛**。把 JD 里的原词用进简历：

| JD 用词 | 你简历该写 |
|---------|-----------|
| 接口测试、Postman | 别写"API 调试" |
| 缺陷跟踪 | 别只写"提 Bug" |
| CI/CD | 别只写"Jenkins" |
| 测试用例设计 | 别写"写用例" |
| 自动化测试框架 | 别写"自动化脚本" |

## 五、投递渠道与策略

### 5.1 主要渠道对比

| 渠道 | 特点 | 适合 |
|------|------|------|
| **BOSS 直聘** | 直接和 HR/技术负责人聊，反馈快 | 社招主力，**首选** |
| **猎聘** | 中高端岗位多，猎头介入 | 3 年以上 |
| **智联招聘 / 前程无忧** | 岗位量大，传统企业多 | 传统行业、外包 |
| **拉勾** | 互联网公司集中 | 互联网岗位 |
| **公司官网 / 公众号** | 大厂唯一正规入口 | 大厂校招社招 |
| **内推** | 简历直达，反馈快 | **效率最高**，优先找 |
| **校招平台** | 应届生专属 | 应届生 |
| **测试社区**（TesterHome、爱测） | 有内推板块 | 圈子内的机会 |

### 5.2 内推的实际价值

!!! tip "内推是最被低估的渠道"
    内推的价值不只是"简历直达"，具体好处：

    - **绕过初筛**：很多公司的内推简历由内部员工直接转给用人部门
    - **反馈快**：可以问到进度，不像网申石沉大海
    - **有信息**：内推人能告诉你团队真实情况、面试重点

    **怎么找内推**：
    1. 前同事、同学、师兄弟（成功率最高）
    2. 技术社区（TesterHome 有内推专区）
    3. 脉脉、LinkedIn 找目标公司员工
    4. 招聘平台直接问 HR"是否支持内推"

    找人内推时的**第一句话**很关键：

    ```
    ❌ "在吗？帮我内推一下。"
    ✅ "你好，看到贵司在招软件测试工程师，我有 X 年测试经验，
        做过接口自动化和性能测试，简历在这份文件里。
        如果方便的话能否帮忙内推？不方便也没关系，谢谢。"
    ```

### 5.3 投递节奏

```text
错误做法：
  一次性投 50 家 → 简历还没优化好 → 大量被拒 → 打击信心

推荐做法：
  第一批（1-2 周）：投 5-8 家"练手岗"（匹配度 50-60%）
    → 目的是试水，看简历有没有问题、面试常问什么
    → 面试后立刻复盘修改简历

  第二批：投 10-15 家"目标岗"（匹配度 70%+）
    → 用优化后的简历，重点准备

  第三批：投 5-10 家"冲刺岗"（匹配度 60-70% 但公司好）
    → 放在后面，因为这时你的面试状态最好
```

!!! warning "不要把所有好机会放在第一批"
    第一批面试时你的表达、项目讲解、技术回答都不成熟。把最想去的公司放在后面投——这是真实经验，不是理论。

### 5.4 投递记录表

用表格管理，避免混乱：

| 公司 | 岗位 | 渠道 | 投递日期 | 状态 | 面试轮次 | 复盘要点 |
|------|------|------|----------|------|----------|----------|
| XX 科技 | 接口测试 | BOSS | 03-01 | 待面试 | - | - |
| XX 网络 | 自动化测试 | 内推 | 02-28 | 已挂 | 二面 | 框架分层没讲清 |
| XX 信息 | 功能测试 | 猎聘 | 02-25 | 已 offer | 3 轮 | 缺陷定位讲得好 |

**状态流转**：已投递 → 已读 → 约面 → 一面 → 二面 → 三面 → HR 面 → 背调 → offer

## 六、判断一个岗位值不值得投

不是所有岗位都值得花时间。用下面几个问题筛：

### 6.1 岗位质量判断

| 信号 | 含义 | 建议 |
|------|------|------|
| JD 描述含糊，没有具体技术栈 | 可能是外包或岗位定位不清 | 谨慎 |
| 职责包含"听从安排""服从分配" | 外包驻场 | 明确问清 |
| 要求精通 5 个以上不同方向 | 一人多岗，工作强度大 | 谨慎 |
| 强调"抗压能力强"多次出现 | 加班严重 | 谨慎 |
| 技术栈描述具体、分方向 | 正规技术团队 | 推荐 |
| 有明确的自动化/平台建设内容 | 技术成长空间大 | 推荐 |

### 6.2 要问清的关键信息

面试前或面试中可以问（**HR 面一定要问**）：

```text
1. 这个岗位是正式编制还是外包？（关键！影响薪资和发展）
2. 团队多少人？测试团队多少人？
3. 主要做什么产品的测试？是自研还是给客户做？
4. 工作地点会不会变动？（外包常见问题）
5. 版本迭代节奏是怎样的？加班情况？
6. 有没有自动化/测试平台的建设规划？
```

!!! warning "外包岗的识别"
    **外包不是不能去**，但要清楚代价：

    | 特征 | 说明 |
    |------|------|
    | "驻场""甲方现场" | 你在甲方办公，但人事关系在乙方 |
    | 薪资写"5K 环普办公" | 典型外包表述 |
    | 招聘方是"信息技术有限公司"但岗位是给别的公司做 | 外包公司 |
    | 面试流程极快（当天给 offer） | 外包常批量招人 |

    **外包的影响**：薪资偏低、技术成长受限、简历上项目归属不清。
    **但对应届生**：可以接受，先积累实战经验，1-2 年后跳槽。

## 七、投递期的心态与节奏

!!! abstract "三个现实认知"
    **一、被拒是常态**
    投 20 家、进 3 家面试、拿 1 个 offer 是正常比例。被拒不代表能力不行，可能只是**匹配度**或**岗位已招满**。

    **二、面试是练出来的**
    第一次面试讲项目会磕巴，第五次就顺了。所以要把"不太想去"的公司排在前面——这是**故意的练习机会**。

    **三、时间线比想象的长**
    从投递到 offer，正常需要 **3-8 周**（含多轮面试、审批、背调）。要预留时间，别等到必须入职才开始投。

## 八、投递自查清单

**投递前**
- [ ] 已按 JD 调整技能栈顺序
- [ ] 已按 JD 调整项目侧重点
- [ ] 简历关键词与 JD 对齐
- [ ] 确认学历/年限符合硬性门槛
- [ ] 匹配度 ≥ 50%

**沟通中**
- [ ] 内推请求的话术得体
- [ ] 已问清是正式编还是外包
- [ ] 已记录投递信息到表格

**投递后**
- [ ] 记录状态，跟进进度
- [ ] 每次面试后立刻复盘
- [ ] 根据面试反馈迭代简历
