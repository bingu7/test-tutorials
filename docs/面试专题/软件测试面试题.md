# 软件测试面试题

这一页整理软件测试基础面试题。每个问题都给出回答思路和新手容易踩的坑。

## 软件测试的目的是什么？

不推荐回答：

```text
测试就是找 Bug。
```

推荐回答：

```text
软件测试的目的是发现问题、评估质量风险，帮助团队判断软件是否满足需求、是否具备上线条件。
找 Bug 是测试的一部分，但测试还包括需求分析、用例设计、风险评估、回归验证和测试报告。
```

## 测试流程是什么？

可以这样回答：

```text
一般包括需求分析、测试计划、测试用例设计、测试执行、缺陷提交、缺陷回归、测试报告。
如果是敏捷项目，测试会更早参与需求评审，在开发过程中同步准备用例和测试数据。
```

面试加分点：

- 提到需求评审阶段就要发现需求不清楚的问题。
- 提到缺陷修复后需要回归。
- 提到上线前要做冒烟或主流程验证。

## 你怎么设计测试用例？

回答思路：

```text
我会先理解需求和业务流程，再从正常流程、异常流程、边界值、权限、兼容性、数据校验等角度拆测试点。
常用方法包括等价类、边界值、场景法、判定表、错误推测法。
```

举例：

```text
比如登录功能，我会测正确账号密码、错误密码、手机号为空、格式错误、账号禁用、连续输错锁定、登录后刷新和退出登录。
```

## 缺陷严重程度和优先级有什么区别？

可以这样回答：

```text
严重程度表示缺陷对系统或业务的影响，比如是否阻塞主流程、是否导致数据错误。
优先级表示修复顺序，受版本计划、业务影响、出现频率影响。
严重程度高的缺陷通常优先级也高，但不一定完全相同。
```

例子：

- 支付金额错误：严重程度高，优先级高。
- 首页 Logo 轻微偏移：严重程度低，但如果今天要发布品牌页面，优先级可能提高。

## 冒烟测试和回归测试有什么区别？

```text
冒烟测试是在新版本提测或部署后，先验证核心流程是否可用，判断是否值得继续深入测试。
回归测试是在缺陷修复或功能变更后，验证原有功能是否被影响，确认问题没有复现。
```

## 如果需求不清楚怎么办？

推荐回答：

```text
我会先把不清楚的点列出来，结合原型、接口文档、历史逻辑和竞品行为提出问题，在需求评审或群里确认。
确认后的结论要记录下来，避免后续开发、测试、产品理解不一致。
```

不要回答：

```text
我先按自己的理解测。
```
