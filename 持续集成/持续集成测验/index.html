    持续集成测验¶

    测验说明

    本测验用于检验持续集成/持续部署知识的掌握程度。共 15 道选择题，覆盖 CI/CD 概念、Jenkins Pipeline、GitHub Actions、Docker 应用和质量门禁。

    📙 中级难度 ⏱ 约 20 分钟 📝 15 道选择题

    测验反馈

    提交答案后，系统会显示： - 得分和正确率 - 错题分析和薄弱知识点 - 复习建议和推荐教程 - 下一步学习建议

    选择题¶

    持续集成（CI）的核心实践是什么？
    💡 持续集成强调开发人员至少每天一次将代码集成到主干分支，每次集成自动触发编译、单元测试和接口测试，尽早发现和修复集成问题，避免"集成地狱"
    以下关于 CI 和 CD 的描述，哪个是正确的？
    💡 CD 有两种含义：持续交付确保代码随时可发布，但需要人工审批后部署；持续部署则完全自动化，代码通过测试后自动部署到生产环境
    在 Jenkins 声明式 Pipeline 中，以下哪个关键字用于定义流水线的各个阶段？
    💡 Jenkins 声明式 Pipeline 使用 pipeline → stages → stage 结构。stage 定义流水线的各个阶段，steps 定义阶段内的具体操作，node 是脚本式 Pipeline 中的概念
    以下 Jenkinsfile 语法中，哪个是正确的声明式 Pipeline 结构？
    💡 Jenkins 声明式 Pipeline 必须以 pipeline 块开始，包含 stages 块，每个阶段用 stage 定义，具体操作放在 steps 块中
    以下哪种方式可以自动触发 Jenkins Pipeline 执行？
    💡 Jenkins 支持多种自动触发方式：Git Webhook、定时构建、轮询 SCM、其他 Pipeline 触发。Webhook 是最常用的方式，实现真正的持续集成
    在 GitHub Actions 中，一个 Workflow 文件应该放在哪个目录下？
    💡 GitHub Actions 的 Workflow 文件必须放在仓库的 .github/workflows/ 目录下，使用 YAML 格式编写，通过 on 字段定义触发条件
    在 GitHub Actions 中，以下哪个 on 配置可以在代码推送到 main 分支时触发 Workflow？
    💡 GitHub Actions 使用 on 字段定义触发事件。on: push: branches: [main] 表示当代码推送到 main 分支时触发，还可以使用 pull_request、schedule、workflow_dispatch 等
    在 GitHub Actions 中，以下关于 Job 和 Step 的描述，哪个是正确的？
    💡 GitHub Actions 的结构是 Workflow → Job → Step。不同 Job 默认并行执行（可用 needs 设置依赖），同一个 Job 内的 Step 按顺序串行执行
    在 CI/CD 中使用 Docker 的主要优势是什么？
    💡 Docker 容器化将应用及其依赖打包在一起，解决了环境不一致问题。在 CI/CD 中可以使用 Docker 镜像作为构建环境，也便于快速创建和销毁测试环境
    以下 Dockerfile 指令中，哪个用于指定基础镜像？
    💡 FROM 指令指定构建镜像的基础镜像，是 Dockerfile 的第一条指令。RUN 执行命令，COPY 复制文件，CMD 指定容器启动时的默认命令
    一个标准的 CI/CD 流水线通常包含以下哪些阶段？
    💡 标准的 CI/CD 流水线通常包括：代码提交 → 构建 → 单元测试 → 集成/接口测试 → 代码质量检查 → 部署到测试环境 → 验收测试 → 部署到生产环境。每个阶段都可能设置质量门禁
    在 CI/CD 流程中，构建制品（Artifacts）应该存储在哪里？
    💡 构建制品应存储在专用的制品仓库中，这样可以版本化管理、控制访问权限、避免 Git 仓库臃肿，并且方便在不同环境间传递和部署
    质量门禁（Quality Gate）在 CI/CD 中的作用是什么？
    💡 质量门禁是在 CI/CD 流水线中设置的检查点，定义了代码必须满足的条件。不满足条件时流水线会失败，阻止问题代码进入下一阶段，确保软件质量
    在 CI/CD 流水线中集成代码质量扫描工具，以下哪个是常用的代码质量平台？
    💡 SonarQube 是最流行的代码质量和安全扫描平台，支持多种编程语言，可以检测代码异味、Bug、安全漏洞和测试覆盖率，通常集成在 CI 流水线中作为质量门禁的一部分
    在 Jenkins 声明式 Pipeline 中，如何实现多个阶段并行执行？
    💡 Jenkins 声明式 Pipeline 支持在 stage 内部使用 parallel 块并行执行多个分支。例如可以同时在不同浏览器上运行 UI 测试，或同时执行单元测试和接口测试，提高流水线执行效率
